# CEO 模式

## 一、产品定义

CEO 模式是 Magic 的显式 Multi-Agent 协作方式。当前会话的主 Agent 承担 CEO 职责，负责判断如何拆解、组织会话成员、协调依赖、整合结果并向用户汇报。

CEO 模式解决的是“单个 Agent 直接完成不够可靠或不够高效，但用户又不想自己做项目经理”的问题。

本文只描述会话级 CEO 协作及其成员关系，不定义工程级 PM 的长期组织契约。模式作用域、进入、退出和与代理方式的连续性，以《工作模式与切换》为共同依据。

## 二、用户心智

> **我把目标交给 CEO，由 CEO 负责组织团队完成。**

用户是最终决策者。CEO 不是切换后出现的另一个陌生 Agent，而是当前会话主 Agent 采用的组织职责。它负责协作组织和结果整合，不取代用户做最终的高风险或价值判断。

## 三、核心循环

```text
说目标 → CEO 复用或增加成员 → 成员执行与协作 → 必要时用户拍板 → CEO 汇总 → 交付
```

组队和开始协作默认不要求用户逐项批准。CEO 应优先复用当前会话中已经适合该任务的成员，也可以按当前任务动态创建新的完整 Agent 会话。只有真正影响目标、范围、风险或交付的决策，才进入用户检查点。

## 四、CEO 的职责

CEO 负责：

- 理解用户目标和约束
- 判断是否需要多 Agent 协作
- 根据当前任务为队员分配调研专家、架构专家、实现负责人、测试评审等任务级职责
- 决定任务依赖和并行关系
- 在必要时让队员继续委派
- 组织交叉验证、辩论或圆桌评审
- 汇总不同队员的结果
- 识别冲突、缺口和未完成事项
- 向用户说明事实、判断和建议
- 对最终交付负责

CEO 不应把每个内部选择都转交给用户，也不应把没有依据的结果包装成完成。

## 五、会话成员

会话成员可以根据 CEO 分配承担研究、实现、验证、评审或其他职责。每个成员都是完整 Agent 会话，拥有独立上下文、任务历史和正常 Agent 工具系统；实际可使用的文件、工具、模型、预算和外部资源由当前授权范围决定。任务角色由 CEO 根据工作需要分配，不是成员永远不变的固定职业。

成员完成一次工作后可以进入空闲状态。下一项 CEO 任务可以继续向原成员派发，也可以增加新成员共同工作。成员保留当前会话内的职责、独立上下文、历史任务和汇报关系，但默认不能被其他会话调用，也不自动成为工程模式中的长期成员。

CEO 也可以为一次局部工作创建完成后不再保留成员关系的 Agent。“临时”只描述任务结束后的保留方式、归属和责任范围，不表示该 Agent 缺少正常工具、上下文或执行能力。是否继续保留为会话成员或挂接为工程成员，取决于后续复用价值和组织授权。

CEO 创建的成员可以在授权范围内继续创建下属 Agent 会话并派发局部任务，但派发链必须保留任务、责任、汇报对象和预算边界。创建下属不会自动扩大任何 Agent 的权限，也不会自动把它变成工程长期成员。

## 六、可见性

CEO 模式需要让用户理解协作正在如何推进，重点展示：

- 当前有哪些队员参与
- 每个队员承担什么任务
- 哪些任务已完成、进行中或受阻
- 结果之间是否存在冲突
- 哪些证据支撑最终判断
- CEO 当前正在等待什么或准备什么
- 哪些内容需要用户拍板

可见性服务于信任和决策，不应退化为用户逐项管理队员。

## 七、用户介入

用户可以：

- 补充目标或约束
- 对当前方向进行插话
- 把后续要求排队
- 停止当前协作
- 对计划进行调整
- 在检查点放行、修改或停止
- 要求查看某个队员的过程或产物
- 直接向某个会话成员补充信息或要求

用户不需要：

- 事先设计全部团队结构
- 手动给每个队员命名职业
- 为每个子任务指定模型
- 批准每一个队员的启动

## 八、CEO 模式与代理模式的边界

代理和 CEO 都可以调用并复用会话成员。区别不在于“有没有子 Agent”，而在于主 Agent 的主要工作：

- 代理模式中，成员辅助主 Agent 直接交付
- CEO 模式中，团队分工、依赖、进度、协商和验收成为显式工作结构

一次 CEO 协作结束后，用户可以回到代理方式；已有会话成员不会被解散，主 Agent 后续仍可单独调用它们。

## 九、CEO 模式与工程模式的边界

CEO 模式的团队归属于当前会话，可以在该会话的多个任务中反复调用；新会话不能直接使用原团队。工程模式的 Agent 团队则归属于具体项目，可以跨本工程的多个会话和任务持续工作并积累项目记忆。

如果当前会话反复出现相同角色、协作关系和长期上下文，系统可以建议用户创建工程。用户可以选择将部分会话成员转为项目成员，但不能静默完成转换。

## 十、完成标准

CEO 模式的一次协作只有在以下内容清楚后才算完成：

- 目标和范围得到回应
- 团队实际完成的工作可追溯
- 关键结论有依据或明确标注为判断
- 冲突意见和未完成事项被说明
- 交付物真实存在并可访问
- 用户知道哪些事项已经结束、哪些还需决定

## 十一、待决策

- CEO 模式的团队是否允许用户在任务中途直接替换队员职责
- 圆桌会议是 CEO 的内置能力，还是独立协作工具
- CEO 模式中用户直接向成员发言时，CEO 如何同步理解与调整计划
- 会话成员保留多久、达到数量上限后如何归档
- CEO 如何判断复用旧成员还是创建新成员
