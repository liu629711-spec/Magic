# 代理模式

## 一、产品定义

代理模式是 Magic 基于 OpenCode 提供的直接 Agent 工作方式。用户提出目标，会话主 Agent 自主完成理解、计划、执行、检查和修正，也可以按需调用其他 Agent 辅助工作；用户不需要管理内部任务拆分和成员协作。

代理模式不是简化版，也不是进入 CEO 模式之前的过渡页。它本身就是一个完整的、高强度的 Agent 工作台。

本文只描述代理方式的用户体验、自主范围和协作者边界。代理与 CEO 的组合、临时调用和默认切换规则，以《工作模式与切换》为共同依据。

## 二、用户心智

> **我交代一件事，你直接帮我做。**

用户关心的是目标、过程状态、修改结果和最终交付，不需要先关心 Agent 的内部组织方式。

## 三、核心循环

```text
说目标 → Agent 理解 → 自主执行 → 检查结果 → 继续修正 → 交付
```

会话主 Agent 可以进行计划、步骤拆解、工具调用和子 Agent 派发。这些动作服务于主 Agent 的直接交付，不因为出现多个 Agent 就自动变成 CEO 模式。

## 四、Agent 的自主范围

在用户已授权的范围内，Agent 可以：

- 阅读相关文件和代码
- 自主选择工具
- 拆解执行步骤
- 修改文件
- 运行检查和测试
- 根据反馈修正结果
- 在任务没有完成时继续推进
- 调用临时执行 Agent 完成局部工作
- 建立和复用当前会话的会话成员
- 汇报完成、部分完成或失败状态

需要用户做出的关键决定仍然必须被明确请求，例如高风险操作、超出授权范围的行为、目标不明确或存在不可逆后果的选择。

## 五、代理模式中的派发与复用

代理模式允许主 Agent 为了完成工作自主安排步骤、调用工具和派发其他 Agent。子 Agent 可以有两种生命周期：

1. **临时执行 Agent**：为一次局部工作创建的完整 Agent 会话，返回结果后默认不保留成员关系。
2. **会话成员**：继续保留成员关系、独立上下文和历史任务的完整 Agent 会话，可以被主 Agent 在后续任务中再次调用或在授权后挂接到其他协作范围。

两者使用同一类正常 Agent 上下文、工具和执行能力；差别只在生命周期、权限、归属、可见范围和责任。是否保留为会话成员，应由后续复用价值、上下文连续性和资源成本共同决定。跨会话使用必须建立明确的挂接、任务和授权关系。

代理模式与 CEO 模式可以复用同一组会话成员。代理模式中负责局部调研的成员，后续可以进入一次 CEO 协作；CEO 协作结束后，该成员也可以继续在代理模式中单独提供帮助。

## 六、代理与 CEO 的边界

代理模式并不等于只有一个 Agent。只要会话主 Agent 仍然是主要执行者和整合者，其他成员承担范围清楚的辅助工作，就仍然属于代理模式。

当多条工作线需要持续协调，成员之间出现复杂依赖、交叉评审或反复协商，主 Agent 的主要职责转为分派、追踪、调整和验收时，才适合采用 CEO 模式。

系统不能仅根据子 Agent 数量决定工作方式，也不能为了展示 Multi-Agent 能力而削弱代理模式的自主派发。

## 七、用户可见内容

默认优先呈现：

- Agent 当前正在做什么
- 重要的文件修改
- 检查和验证结果
- 需要用户决策的事项
- 当前任务是否继续推进
- 最终交付和未完成部分

当主 Agent 调用其他成员时，默认只需要轻量显示“有协作者正在提供帮助”。用户展开后可以查看成员任务、状态和结果，但不会因此被迫进入团队管理界面。

默认不要求用户处理：

- 每一个内部步骤
- 每一次工具调用
- 内部计划的全部细节
- Agent 是否应该拆成几个小步骤
- 用户不需要知道的底层执行日志

用户可以在需要时展开过程，但“可见”不等于“必须管理”。

## 八、代理模式的 CEO 建议

当团队协作已经成为工作的主要组织结构时，系统可以给出非阻塞的 CEO 模式建议。建议必须满足：

- 当前工作不被强制打断
- 当前已完成结果不丢失
- 用户可以选择继续代理模式
- 不把代理模式描述成能力不足
- 不自动创建长期工程团队
- 不因为主 Agent 调用了子 Agent 就机械触发

## 九、完成标准

代理模式的一次任务只有在以下内容明确后才算完成：

- 用户目标已经得到回应
- 实际执行过的工作有事实依据
- 文件或代码修改已经真实落盘
- 验证结果被如实说明
- 未完成、失败或等待事项没有被隐藏
- 用户知道下一步是否需要介入

## 十、待决策

- 代理模式中的连续工作是否需要独立任务面板
- Agent 何时可以主动询问用户，何时应继续尝试
- 哪些子 Agent 默认保留为会话成员，哪些任务结束后释放
- 代理模式下会话成员的轻量状态应该展示到什么程度
