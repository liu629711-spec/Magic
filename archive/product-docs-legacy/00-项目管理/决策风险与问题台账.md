# 决策、风险与问题台账

## 1. 已确认决策

| 编号 | 决策 | 影响 |
|---|---|---|
| D-01 | 代理 / CEO 与普通工作 / 工程是两个维度 | UI 和对象模型不能做成三选一等级 |
| D-02 | 正式任务唯一当前责任人，任务状态与运行状态分离 | 必须有 Magic 自有任务账本 |
| D-03 | 工程可关联多个资源，代码重叠修改通过独立空间和授权合并 | 资源变更不能直接改写任务结果 |
| D-04 | 同一工程同一时间只有一名 PM，交接显式记录 | 交接不自动转移任务、审批或历史责任 |
| D-05 | 权限、预算、风险和有效期分开治理 | 三档授权入口不能替代硬边界和系统禁止项 |

## 2. 当前阻塞 / 风险

| 编号 | 类型 | 事项 | 责任人 | 关闭条件 |
|---|---|---|---|---|
| R-01 | 阻塞 | OpenCode runtime、commit/tag、protocol/client contract 尚未锁定 | OpenCode 后端 | 版本锁定并可复现 |
| R-02 | 阻塞 | TaskAttempt 在断连、重启、重试、停止、审批和副作用下的收敛证据不足 | AgentCore 后端 | F-10 全组合场景通过 |
| R-03 | 高风险 | Magic 任务账本与底座 Session/Run 映射基数未完成实机确认 | 后端 + AI 核心 | 映射表、事件证据和限制说明完成 |
| R-04 | 高风险 | 前端若只展示底座状态，可能把等待/失败误报为完成 | OpenCode 前端 | 状态契约和 S-05/S-10 验收通过 |
| R-05 | 中风险 | 首版范围扩张到画布、圆桌、跨工程协作 | PM | 任何扩展都通过增量门槛和用户价值评审 |

## 3. 待技术核查

- OpenCode 的 canonical server runtime、事件游标、重放和幂等能力。
- Magic 任务、TaskAttempt、任务会话、回合与底座 Session/Run 的最小基数关系。
- 停止、恢复、审批等待和外部副作用的真实可观测性。
- 文件/Git/MCP/网络资源的隔离、冲突、审计和合并能力。
- 成本预留、归集、超限拦截和撤销后的历史记录。

## 4. PM 决策规则

- 产品语义由 PM / 用户裁定；技术只提交证据、代价、风险和替代方案。
- “源码存在”“测试存在”“历史项目做过”不能单独关闭技术核查。
- 任何新对象、长期身份、权限扩大、默认自动化或外部副作用都必须补充范围、时效、责任、撤销和验收条件。
- 风险关闭必须附证据链接；没有证据只能标记“缓解”，不能标记“完成”。

历史裁定、会议发言和详细专题保留在 `90-支撑材料/`、`99-历史会议/`，不在本台账之外产生第二个当前版本。
