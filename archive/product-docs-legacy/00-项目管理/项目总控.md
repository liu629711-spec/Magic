# Magic 项目总控

## 1. 一句话目标

让用户可以直接交代目标；简单工作由代理完成，复杂工作可由 CEO 组织，长期工作在用户确认后形成工程团队，并在整个过程中保持责任、状态、权限和交付结果可追溯。

## 2. 当前状态

| 项目维度 | 当前结论 |
|---|---|
| 产品方向 | **Go**：代理、CEO、工程是两个可组合维度 |
| 产品契约 | **已形成基线**：对象、责任、状态、信息和权限边界已定义 |
| 技术收敛 | **进行中**：需要锁定 OpenCode 版本、运行时和协议事实 |
| 首次正式开发 | **No-Go**：F-10 组合验收尚未形成可重复证据 |
| 下一转阶段 | F-10 通过后，进入限定首切片 Conditional Go |

## 3. 当前只追三件事

1. **锁定底座事实**：OpenCode commit/tag、server runtime、canonical protocol/client contract。
2. **闭合任务账本**：证明 `MagicTask / TaskAttempt` 在断连、重启、重试、停止、审批和副作用下最终收敛。
3. **准备首切片验收**：单用户、单工程、1 名 PM、2 至 4 名成员、可追踪任务和真实产物。

## 4. 首版边界

首版只验证一个真实工程的完整闭环：用户建工程、确认 PM、配置少量成员、派发任务、执行产物、汇报收口、用户查看和任务恢复。多层 PM、跨工程借调、无限团队、完整圆桌、自动组织演化和任意无损模式切换均后置。

| 责任域 | 责任人 | 交付物 |
|---|---|---|
| 产品基线、范围和裁定 | Magic 项目 PM | 本工作台、产品基线、决策台账 |
| OpenCode 底座事实与运行时 | OpenCode 后端架构负责人 | 版本锁定、运行时核查、协议证据 |

| Agent 协作与记忆边界 | AI 核心负责人 | 成员复用、结果回传、记忆/事实隔离方案 |
