# Magic 产品基线

## 1. 产品定义

Magic 是建立在 OpenCode 之上的 AI 工作台。OpenCode 提供 Agent 执行、工具、文件和底层会话能力；Magic 负责工作方式、长期工程组织、任务账本、责任、信息、权限和真实交付。

## 2. 两个可组合维度

| 维度 | 选项 | 解决的问题 |
|---|---|---|
| 会话工作方式 | 代理 / CEO | 当前目标由主 Agent 直接完成，还是显式组织协作 |
| 长期组织形态 | 普通工作 / 工程 | 是否建立 PM、长期成员、项目事实和持续治理 |

代理不是低级模式，CEO 不是强制升级；工程不是聊天、文件夹或 Agent 数量的别名。用户可以直接开始，也可以在需要时主动展开协作或建立工程。

## 3. 必须保持的边界

- 临时 Agent、会话成员、项目成员、主 Agent、PM、Agent 身份和运行实例分开。
- 工作区、文件夹、资源、会话、任务、回合、运行和产物分开。
- 正式任务始终只有一名当前责任人；运行成功不等于任务完成。
- 任务状态与运行状态分开；等待、失败、部分完成、停止、取消和断连不得包装成成功。
- 文件共享不等于共享身份、私有上下文、记忆、权限或项目事实。
- 创建工程、长期成员、权限扩大、跨边界共享和持久化事实必须可见、可审计、可撤销。
- 取消运行不撤销已经发生的写入、付费、命令或其他外部副作用。
- 不承诺执行中任意无损切换；无法无损时必须说明影响并提供继续、暂停或重新规划路径。

## 4. 首版用户体验

用户应能用自然语言开始任务，看到关键进度、当前责任人、结果、阻塞和风险；内部协作默认由 Agent 管理，只有决策、权限、冲突或用户主动要求时才打断。所有交付都必须能指向真实文件、测试、事实或外部结果。

## 5. 首版产品范围

| 纳入 | 后置 |
|---|---|
| 单用户、单工程、一名 PM、2 至 4 名成员 | 多层 PM、无限层级和跨工程成员 |
| 任务、子任务、任务会话、运行、产物、责任和计划 | 完整圆桌、多人实时画布和组织演化 |
| 代理、CEO、成员复用和用户直达 | 自动建立完整团队、永久在线 Agent |
| 等待、停止、失败、部分完成、取消、归档和重开 | 全量私有记忆自动共享 |
| 权限确认、预算记录、资源变更和冲突可见 | 复杂多组织权限和成员市场 |
