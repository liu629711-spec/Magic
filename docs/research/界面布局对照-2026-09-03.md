## 用户 mockup 的已确定布局

`UI mockup/code.html` 将窗口划分为三个工作区：

- 左侧 `navigation-sidebar`：Magic 工程入口、搜索/通知、新对话、拉取请求、已安排、插件、置顶、项目、最近，以及底部设置/帮助。
- 中央 `main-chat-area`：欢迎内容、任务类型入口和底部 `chat-input-container`。输入区包含项目选择、文本输入、访问权限、模型/推理强度和发送按钮。
- 右侧 `tools-sidebar`：浏览器、终端等上下文工具，并以快捷键提示显示入口。

这是已有参考界面的事实记录；后续 Magic 内容应填入这些区域，而不是另起一套页面骨架。

## Claude Code 官方桌面布局

以下事实来自 Anthropic 的 [Claude Code Desktop application](https://code.claude.com/docs/en/desktop) 与 [Manage sessions](https://code.claude.com/docs/en/sessions)：

- Claude Desktop 有 `Chat`、`Cowork`、`Code` 三个标签；Claude Code 的开发工作集中在 `Code` 标签。
- `Code` 标签的左侧栏列出会话，支持按状态、项目和环境筛选/分组，并支持多个会话并行或拆分显示；每个会话独立拥有聊天记录、项目目录和代码变更。
- 当前会话由可排列的 panes 组成：chat、diff、browser、terminal、file、plan、tasks、subagent；pane 可拖拽重排或调整大小。
- 会话底部 prompt 区配置运行环境（Local/Cloud/SSH/WSL）、项目文件夹、模型和 permission mode；权限模式可在会话中切换。
- 代码变更通过 Diff view 审阅：左侧文件列表、右侧变更内容，可逐行评论；Transcript view 可切换 Normal/Verbose/Summary。
- 模型选择旁的 usage ring 展示当前会话上下文用量和周期用量；终端、文件、浏览器和 PR/CI 状态作为会话内工具或 pane 展示。

这些是 Claude Code 官方桌面文档明确描述的区域与交互，不等同于 Magic 的功能承诺。

## Codex 官方桌面布局

以下事实来自 OpenAI Docs 的 [Codex 官方开发者文档](https://developers.openai.com/codex) 首页桌面界面示意和 [ChatGPT desktop app](https://learn.chatgpt.com/docs/app) 页面：

- 左侧导航包含 `New chat`、`Search`、`Scheduled`、`Plugins`、`Sites`、`Pull requests`、`Pinned`、`Projects` 和 `Chats` 等入口。
- 中央主区以当前目标/对话为主，并提供任务入口：理解代码、构建功能或工具、审查代码、修复问题；同时选择 Project 和运行环境（例如本机）。
- Composer 位于中央工作区底部，模型与推理强度靠近发送操作；桌面应用面向 Projects、文件和长时任务。
- Codex 的项目、聊天、计划任务和工具入口属于同一桌面应用导航体系，不应在 Magic 中拆成未经确认的新一级导航。

这些是 OpenAI Docs 当前公开的 Codex 桌面界面事实；Magic 只借鉴区域位置和信息层级。

## Zcode 官网已确认的桌面 Agent 布局

以下事实来自 [ZCode 官方中文页](https://zcode.z.ai/cn) 页面展示的桌面工作区示例：

- 顶部工作区操作：`新建任务`、`打开工作区`、`技能`；任务列表位于左侧，并按工作区/项目分组，可展开查看最近任务步骤，也可切换归档任务。
- 中央执行区：顶部显示当前目标、工作区路径、Git 分支和工作区操作；中部是按时间顺序排列的 Agent 会话/执行记录，工具调用和执行摘要可以展开。
- 底部 Composer：继续输入框、添加上下文、变更前确认、模型、推理强度和发送操作集中在执行区底部。
- 右侧状态区：提供 Git tools、Changes、分支、Goal、Progress 等上下文详情；Changes 显示变更统计，Goal 显示目标完成度、耗时和 token，Progress 列出步骤。
- 终端作为中央工作区底部/右侧可切换的上下文工具出现，不替代 Agent 会话主区。

这些是 Zcode 官网公开展示的布局事实，不等同于 Magic 的功能承诺；Magic 只借鉴区域位置和信息层级，具体字段仍以自身 PRD 与后端契约为准。

## 桌面 Agent 的对照事实

### 1. 任务与计划

Claude Code、Codex 和 Zcode 均采用任务/会话列表 + 当前 Agent 工作区；Claude Code 的 Plan/Tasks pane、Codex 的 Projects/Chats 导航和 Zcode 的 Progress/任务列表已核实。

### 2. 执行过程与会话流

Claude Code 的 chat transcript、Codex 的中央任务对话和 Zcode 的中央执行会话都承载 Agent 的连续执行过程；具体 Magic 事件字段仍以自身契约为准。

### 3. 审批与权限

Claude Code 将 permission mode 放在会话底部 prompt 区，Zcode 将“变更前确认”放在 Composer；Codex 的权限入口仍以官方桌面版本实际可见控件为准。

### 4. Diff、产物与验收证据

Claude Code 明确提供 Diff view、文件列表和逐行评论，Zcode 明确提供右侧 Changes；Codex 的结果区域需按当前桌面版本继续核对。

### 5. 成本与运行用量

Claude Code 在模型选择旁显示 usage ring，Zcode 在 Goal 区显示耗时和 token；Codex 的用量入口以当前桌面版本为准。

### 6. 状态与项目更新

Claude Code 通过会话状态/CI 状态，Codex 通过任务与聊天列表，Zcode 通过 Goal/Progress 展示执行状态；Magic 状态语义仍以自身契约为准。

## 对 Magic 的当前映射

下表只把 Magic 已确认的领域对象映射到成熟产品已有的位置；它不是新增页面提案。

| Magic 内容 | 成熟产品中的对应位置 | Magic 应放置的参考区域 |
| --- | --- | --- |
| Task 列表/筛选/状态 | Zcode 左侧工作区/项目任务列表；Claude Code 会话侧栏；Codex Projects/Chats | 左侧 mockup 现有入口进入后的中央工作区 |
| Task 目标、责任人、验收标准 | Zcode 中央目标与右侧 Goal；Claude Code 当前会话上下文；Codex 中央任务区 | 中央任务区；详情属性放右侧 |
| Plan step / 子 Task | Zcode 右侧 Progress；Claude Code Plan/Tasks pane；Codex 计划区 | 中央会话区可展开，完整计划放右侧 |
| Attempt、步骤、事件账本 | Zcode 中央执行会话；Claude Code transcript；Codex 中央任务对话 | 中央主区按时间顺序展示 |
| 审批、权限确认 | Zcode Composer“变更前确认”；Claude Code prompt 区 permission mode；Codex 权限控件 | 触发操作的中央会话流/底部 Composer |
| Diff、测试、产物、成本、副作用 | Zcode 右侧 Changes；Claude Code Diff view；Codex 结果区 | 右侧工具或详情区 |
| 成本、Token、duration | Zcode Goal；Claude Code usage ring；Codex 用量入口 | 当前 Attempt 运行详情区 |
| unknown、失败、取消 | Zcode 运行状态区域；Magic 自身状态契约 | 中央会话流中的显式状态 |

## 结论边界

1. 当前已确认 mockup、Zcode 官网、Claude Code 官方桌面文档和 Codex 官方文档都把 Agent 工作区作为中心，配合侧栏任务/会话和上下文工具。
2. 具体新增页面、一级导航和视觉样式仍需以 Magic 产品契约与 mockup 为准，不直接复制外部产品。
3. Magic 的状态、权限和验收规则仍以仓库 PRD 与后端契约为准；本研究只记录桌面 Agent 的布局证据。
