# Magic 第一版范围确认

> **本版要点**：对齐 DSH 插件架构；删除对已作废的后端 / 数据库 / 前端方案与 F-10 记录的引用；把 AgentCore 核心能力纳入 V1；工程组织排除在 V1 之外（PRD-03 暂缓）。
>
> 本文初版于 2026-09-02，2026-09-11 修订。

本文是第一版范围对齐记录，不是新的 PRD。产品语义以 `docs/01-产品/PRD-01` 至 `PRD-05` 为准；本文只把第一版要实现的范围和技术限制收敛成可执行清单。

当前 `main` 把 Magic 做成 DSH 插件，不重写底座。`patches/web.patch.yml` 实际加载 `magic-work-mode`、`magic-ceo`、`magic-ceo-ui` 三个插件；`magic-engineering` 已实现但**未加载**（工程暂缓）。旧的 Rust/Tauri 桌面实现、后端 / 数据库 / 前端方案与 F-10 记录都在 `old-design` 分支，只用于追溯。

## 2. V1 的真实状态规则

1. 客户端关闭窗口不等于取消任务；重新打开后先读取 Magic 状态并进行对账。
2. DSH 重启后不能自动推断任务成功；无法确认时显示“重启后状态未知”。
3. 取消不撤销已经发生的文件写入、命令、费用或外部副作用。
4. 重试一定创建新的 Attempt，旧 Attempt 和历史费用保留。
5. 同一幂等键只能对应一次 Magic 派发；请求内容变化必须报冲突。
6. Task 只有在验收证据满足并由责任人收口后才是“已完成”。

## 3. 明确不纳入 V1

- **工程组织与长期团队**（PM、项目成员、跨工程借调、自动组织演化）——PRD-03 暂缓；
- **后置能力域**：文件夹与多工作区的产品语义、笔记墙 / 看板、辩论、升级 / 交接、Playbook、成本配额、可观测回放；
- DSH 进程级自动接管未完成执行；
- 多用户、多工程、多层 PM；
- 两名以上成员的自动并发编排和自动合并冲突；
- 自动撤销、自动补偿和对已经发生副作用的回滚承诺；
- 任意无损的运行中模式切换；
- 多人实时画布、复杂团队看板和完整原始思维展示。

## 4. 进入开发的验收门槛

只有以下条件同时满足，才把范围标记为 `confirmed` 并进入实现：

- 用户确认第 1 节的范围和第 3 节的排除项；
- DSH 版本、Profile/Bundle、插件加载方式和扩展点清单被锁定并写入实现配置；
- 建立**升级体检**：在锁定版本上真实加载三个插件并 typecheck，DSH 改字段名时升级即可报错（技术文档 §3.3）；
- **底座契约核查通过**：证明 Magic `TaskAttempt` 与 DSH 执行证据的最小绑定模型，能在断连、事件缺口、进程重启、重试、停止、审批和副作用组合下收敛（原 F-10，见 PRD-04 §6、§21）；
- 首个真实交付场景的验收证据已定义：任务、Attempt、审批、产物、费用和副作用均可追溯；
- AgentCore 能力域的 V1 / 后续边界经用户确认（技术文档 §4.2 / §4.3）。

用户已确认本清单，状态为 `confirmed`。前端视觉细节可以在开发过程中逐步完善，但插件对外契约、状态、事件、幂等和验收语义按本清单执行。
