# 五方共同签署结论

## F-01 产品核心

U-01 至 U-12 已确认。Magic 是以 OpenCode 为执行底座、由 Magic 自持任务、身份、责任、事实、产物、权限和工程组织的产品层。底座运行事实不决定产品任务成功。

五位总监均确认真正理解：Magic 的价值不是 Agent 数量或复杂编排，而是用户不必管理底层运行时，系统仍能诚实回答谁负责、做到哪里、依据是什么、留下什么、发生了什么副作用以及下一步由谁处理。

## F-02 首版生产拓扑

```text
OpenCode App 宿主中的 Magic 领域 UI
        ↓
Magic Control Plane / 账本 / Projection
        ↓
OpenCode Adapter
        ↓
canonical OpenCode runtime
```

`Control Plane` 表示逻辑权威，不预设必须拆成独立进程或微服务。Magic 账本及 Projection 是任务产品状态的唯一权威；OpenCode App 原生 store 只保存运行遥测、连接状态或可重建缓存。

AgentCore 是旧产品经验、机制与对照实现来源，首版不是必经独立 runtime。未来引入必须另做 ADR、直连/中间层对比 F-10 和用户裁定。

## F-03 当前阶段

项目正式处于：**开发前技术发现与契约收敛期**。

允许立即编写 F-10 harness、故障注入、Adapter/Projection spike、协议探针和 fixture UI。所有此类代码必须标记为 discovery/spike/non-production，不得反向冻结生产 schema、API、完整状态机或排期。

## F-04 canonical runtime/client

独立 V2 CLI `serve` 是第一候选，不是已选结论。使用锁定 commit、仓库声明的 Bun 和同源 schema/generated client 比较候选 listener。canonical Adapter client 必须由锁定 commit 的同源 schema/protocol 生成、测试、封装并固定 hash；当前 vendored `1.17.13-v2` client 不得进入 canonical Adapter path。即使完成等价验证，它也只可保留在遗留 UI 兼容路径。

候选选择矩阵可比较多套 listener，但完整阻塞型 F-10 只要求最终入选的 canonical runtime 全量通过。任一 Attempt 只绑定一个 `runtime_lock_id`，不得混用两套写路径。

## F-05 双切片

技术验证切片：`1 Task / 1 基准 Attempt / 1 canonical Session / 1 worktree / 1 approval / 1确定副作用`。基准 Attempt 不是 F-10 数量上限；停止、取消、重试和重开必须产生并验证后续 Attempt。

首次正式产品切片：单用户、单工程、唯一 PM、一个成员、一个正式成员任务、独立 worktree、结构化结果回传、Artifact/ChangeSet/SideEffect 分账及 PM/用户验收。

技术验证切片和首次正式产品切片都必须实际使用版本化 `ContextEnvelope` 与 `TaskResultPacket`。`TaskResultPacket.status_proposal` 只能提出状态建议，不能关闭任务。

首切片为每个正式任务记录唯一 `acceptance_authority_id`：PM 派发的成员任务由当前 PM 验收；用户发起的根任务或工程交付由用户验收。成员任务验收不能自动关闭根任务，根任务验收也不能改写成员任务历史。若发生争议，由根任务的用户验收权决定工程交付是否接受，但每个任务仍只保留自身唯一终态。

双成员、身份复用、PM 交接、冲突合并和完整停止重开交互作为后续独立验收场景。相关对象和不变量在 P0 预留，功能不阻塞首切片。

确定副作用必须覆盖：`SideEffectIntent 已持久化 → 外部动作发生 → receipt/Journal 落盘前崩溃`。无法确认是否发生时，正确结果是 `manual_reconciliation_required`，保留责任人与补偿任务；自动重试或伪成功判失败。

## F-06 F-10 责任

- 单一技术 DRI：OpenCode 后端架构总监，负责 runtime/client lock、harness 总装、故障注入、原始证据和 dossier 完整性。
- AI 核心：语义 oracle、ContextEnvelope/TaskResultPacket、模型不得伪成功和工具 receipt 边界，拥有基于已签署契约的语义否决权。
- AgentCore 后端：Magic-owned Reconciler/Projection、幂等、恢复、SideEffectIntent 和人工补偿边界，拥有收敛实现否决权；不因此引入 AgentCore runtime。
- OpenCode 前端：sync_unknown/gap、Magic Projection client、generated drift 与真实 UI E2E。
- AgentCore 前端：用户可见状态矩阵、诚实终态与旧体验迁移审查。

技术否决必须基于契约违反、可重复测试失败、证据缺失或产品规则被改写。五方均签署后才可判 F-10 Go。

## F-07 P0 三份主文档

1. 《首版生产拓扑与底座锁定 ADR》；
2. 《Magic 最小执行与收敛契约 v0》；
3. 《F-10 与首次开发准入验收规范》。

三份文档必须记录 authority、版本、适用 runtime/client/env、schema/fixture hash、负责人、变更规则和重新验收触发条件。规范性 schema、状态表、fixture、事件映射和证据 manifest 是主文档附件，不能后置到 P1。

## F-08 首次开发判据

唯一生产拓扑与同源 runtime/client/env 锁定、最小执行与收敛契约签署、F-10 全部阻塞场景在同一锁定栈上可重复通过并形成五方接受的证据包时，首次正式产品开发转为限定 F-05 首切片的 `Conditional Go`。

F-10 通过不等于所有故障自动恢复成功。无法自动确认的非幂等副作用收敛到明确人工核对状态也可以通过，但必须保留责任、事实和下一步。
