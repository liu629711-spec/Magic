# F-10 与首次开发准入验收规范

## 技术验证基线

在同一 `runtime_lock_id` 下，以 `1 Task / 1 基准 Attempt / 1 canonical Session / 1 worktree / 1 approval / 1确定副作用` 建立基准。停止、取消、重试和重开必须创建并验证后续 Attempt，不受“1 Attempt”限制。

## 阻塞场景

- 断连、重连和连接恢复但状态未完整；
- 服务进程重启；
- 重复、乱序和缺失事件；
- 审批等待、允许、拒绝和重启恢复；
- 停止、取消、重试和重新打开；
- 文件、Git、网络、付费或其他副作用已发生但 receipt/Journal 未落盘；
- 无法确认副作用时进入人工核对与补偿任务。

每个场景的重复次数、一致性标准和证据字段必须在执行前冻结。通过不要求所有故障自动恢复，但必须诚实收敛到明确状态、责任人和下一步。

## 证据包

保留 runtime/client/env lock、请求、原始事件、cursor、账本快照、Projection、审批、模型/工具记录、Git 状态、Artifact、SideEffectIntent、receipt、人工核对与最终判定。

每个用例分别形成 runtime verdict、Magic convergence verdict 和 semantic verdict，由对应岗位签署。

## 开发门禁

`Product Go` 与 `Pre-development Technical Convergence Go` 已成立。`First Development` 当前 No-Go；本规范、生产拓扑 ADR 和最小执行契约完成签署，全部阻塞场景在锁定栈上可重复通过后，转为限定首次产品切片的 Conditional Go。
