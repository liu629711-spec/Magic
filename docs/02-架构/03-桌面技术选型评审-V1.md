# Magic 桌面技术选型 V1

## 决定

Magic 使用 **Tauri + Yew/WASM + Rust Local Service + DSH**：

- Tauri：窗口、系统权限、启动和安全桥接。
- Yew/WASM：Magic 自有的 Codex 风格三栏产品界面。
- Rust Local Service：Magic API、产品状态、DSH 生命周期和对账。
- DSH：会话、模型、工具和 Agent 执行底座。

## 不采用的方案

不以 `dataelement/dsh-desktop` 为 Magic 基座。它是社区 Electron 宿主，将 DSH Web UI 加载到窗口中；其可替换 UI 插槽不足以承载 Magic 已确认的会话导航、连续三栏、右侧工作区和产品扩展。直接 fork 会同时维护 Electron 壳、DSH UI patch 和 DSH alpha 升级。

Magic 也不嵌入 DSH Web UI。这样会造成两套会话、设置和导航，并失去 Magic 的产品界面控制权。

## 采用理由

1. 保留已经完成的 Magic UI 和产品边界。
2. DSH 承担 Agent 通用能力，避免自研会话、模型、工具和插件运行时。
3. Rust Local Service 是唯一访问 DSH Remote API 的受控边界；DSH launch token 不进入 UI、日志、SQLite 或 Magic API。
4. 桌面壳可以借鉴 DSH Desktop 的打包、隔离 `DSH_HOME`、恢复和 Safe Mode 经验，但不复制其 UI 代码。

## 尚未完成的部署验证

- 打包固定版本的 DSH 与 Node；不依赖开发 checkout。
- 应用数据目录下的隔离 `DSH_HOME`、健康检查、正常退出和失败恢复。
- DSH 版本升级的兼容性回归：会话、模型、凭据、工作区和插件。
- 真实模型与工具执行下的启动时间、内存和恢复行为。
