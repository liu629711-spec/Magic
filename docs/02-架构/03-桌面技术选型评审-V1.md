# Magic 桌面技术选型评审 V1

## 1. 已知约束

- Magic V1 是本地桌面应用。
- 用户需要关闭窗口后再次打开仍能看到任务历史，并对未终结 Attempt 做对账。
- OpenCode V1 是执行底座候选，参考实现以 TypeScript/Bun 为主。
- 产品首版是单用户、单工作区、单工程；不等于可以把所有状态放在内存中。
- 代码必须保留未来替换 OpenCode V2 或 DeepSeek Harness 的 Adapter 接缝。

## 2. 候选方案

### A. Electron + Web Renderer + 本地服务进程

OpenCode 参考项目的 `packages/desktop/package.json` 使用 Electron、electron-vite 和 electron-builder；AgentCore 参考项目的 `apps/desktop/README.md` 明确采用 Electron + React，AI 执行运行在独立 server/sidecar。该方案与现有参考链路最接近，Node/Bun 子进程、文件系统和自动更新工具成熟。

代价是安装包较大、主进程安全边界必须严格设计，渲染层不能直接访问文件系统或执行命令。

### B. Tauri + Rust UI + 本地服务进程

桌面壳更轻，Rust 可以提供更窄的系统权限面；Magic 本地服务和 OpenCode Adapter 也使用 Rust，只有 OpenCode V1 外部进程继续使用 Bun/TypeScript。当前参考项目没有 Magic 的 Tauri/Rust UI 运行链路证据，因此必须通过独立 Spike 验证，不能把“更轻”直接等同于“更适合”。

### C. 纯浏览器 + 本地服务

开发和 UI 调试简单，但不能单独提供桌面窗口、进程生命周期、文件权限和安装升级能力，不满足 V1 的完整交付形态，只能作为渲染层测试模式。

## 3. 评估维度

| 维度 | Electron | Tauri | 纯浏览器 |
|---|---|---|---|
| OpenCode V1 接入 | 低风险，参考项目已有 | 需 sidecar 桥接 | 需额外本地服务 |
| Windows 文件/进程能力 | 成熟 | 成熟但需 Rust 接口 | 不足 |
| 安装包体积 | 较大 | 较小 | 不适用 |
| 主进程安全复杂度 | 高，需严格 preload/IPC | 需 Rust command allowlist | 低但能力不足 |
| Magic 自有代码语言 | TypeScript | Rust（OpenCode 外部进程除外） | TypeScript |
| 当前源码证据 | OpenCode、AgentCore 均有 | Magic 暂无 | 仅适合作为测试 |
| 未来替换执行底座 | 由本地 API/Adapter 决定，与壳无关 | 同上 | 同上 |

## 4. 决定

V1 采用 **Tauri + Rust UI + Rust 本地服务进程**：

- Rust/Tauri：桌面窗口、系统权限、进程生命周期和安全桥接；
- Rust UI：Magic 用户界面，采用 Yew 0.23 + Trunk 编译为 WASM；
- Rust：Magic 本地 API/Worker 和 OpenCode V1 Adapter；
- OpenCode V1：受控执行子进程。

选择依据是 Magic 作为本地桌面 Agent 对安装体积、空闲内存和系统权限有明确要求，同时用户明确选择 Magic 自有代码统一使用 Rust。OpenCode V1 作为外部执行底座不改写。

该决定已经通过 Tauri/Rust UI 和独立 Worker Spike；不能把理论体积/内存优势当成生产预算，真实模型请求、日志和并发仍需在 E2E 阶段测量。

验证记录：`spikes/tauri-desktop-runtime/RESULTS.md`、`spikes/rust-ui-runtime/RESULTS.md`、`spikes/rust-worker-runtime/RESULTS.md` 和 `spikes/rust-ui-capabilities/RESULTS.md`。这些记录分别覆盖桌面壳、Rust UI、本地 Worker 生命周期和 UI 能力边界。

正式进入业务开发前必须完成一个最小可行性 Spike：桌面壳启动本地 API/Worker、拉起 OpenCode V1、应用关闭/重开后完成对账、渲染层不能越权访问本地文件，并记录启动时间、空闲内存、单任务内存和并发任务内存。

## 5. 需要确认的部署问题

1. V1 是否只支持 Windows，还是首版必须同时支持 macOS/Linux？
2. 应用窗口关闭后，是否要求后台继续执行；还是允许用户显式退出后停止 Worker？
3. 是否接受较大的 Electron 安装包，还是安装包体积有硬上限？
4. OpenCode 是否随 Magic 一起打包，还是要求用户单独安装并配置？

以下部署参数仍需在 Spike 中确认：跨平台范围、窗口关闭后的后台执行策略、OpenCode 是否随 Magic 打包，以及安装包和运行内存预算。它们不会改变“Rust/Tauri 桌面层 + Rust UI/本地服务”的职责划分，但会影响打包和生命周期实现。
