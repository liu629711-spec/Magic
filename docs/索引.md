# Magic 文档索引

> 本索引解决两个问题：第一次进入 Magic 应该先读什么，以及不同文档发生口径差异时哪一份优先。当前文档不要求所有读者通读全部资料。

## 三、冲突处理规则

出现口径差异时，按以下顺序处理：

1. 用户最新明确的产品决定。
2. [`产品方向总纲`](01-产品/产品方向总纲.md)中的长期方向和产品不变量。
3. [`Magic最终产品裁定与技术会议输入`](01-产品/Magic最终产品裁定与技术会议输入.md)中的当前首版裁定和门槛。
4. [`Magic产品系统边界与生命周期底图`](01-产品/Magic产品系统边界与生命周期底图.md)中的对象、责任和生命周期基线。
5. 对应专题文档中的详细方案。
6. 历史会议纪要、旧 AgentCore 文档和探索性蓝图。

任何冲突都必须记录并回写，不能由技术或子 Agent 默默选择其中一套。若冲突影响已确认方向，应先回到产品负责人重新裁定。

## 五、结论标记

所有新文档和会议记录必须把结论标记为以下之一：

- **产品不变量**：长期不可违反。
- **首版建议**：用于验证，不是永久限制。
- **待用户裁定**：由技术说明方案和代价，由用户决定。
- **待技术核查**：必须用当前版本和实机证据确认。
- **探索性内容**：用于打开思路，不得写成默认能力。

## 六、技术拆解项目分层

前端与架构拆解按三个项目/阶段组织。当前第一步是对真实 OpenCode 仓库做现状拆解；Magic 是后续目标项目；AgentCore 是已有代码的参考基线：

| 项目 | 前端拆解 | 架构拆解 | 主要产物 |
|---|---|---|---|
| OpenCode 现有项目 | [`03-前端/01-OpenCode/`](03-前端/01-OpenCode/) | [`02-架构/01-OpenCode/`](02-架构/01-OpenCode/) | `OPENCODE_FRONTEND_ARCHITECTURE_BREAKDOWN.md`、`OPENCODE_BACKEND_ARCHITECTURE_BREAKDOWN.md` |
| Magic 目标项目 | [`03-前端/02-Magic-目标项目/`](03-前端/02-Magic-目标项目/) | [`02-架构/02-Magic-目标项目/`](02-架构/02-Magic-目标项目/) | `MAGIC_TARGET_FRONTEND_ARCHITECTURE.md`、`MAGIC_TARGET_BACKEND_ARCHITECTURE.md` |
| AgentCore 现有项目 | [`03-前端/03-AgentCore-现有项目/`](03-前端/03-AgentCore-现有项目/) | [`02-架构/03-AgentCore-现有项目/`](02-架构/03-AgentCore-现有项目/) | `AGENTCORE_EXISTING_FRONTEND_BREAKDOWN.md`、`AGENTCORE_EXISTING_BACKEND_BREAKDOWN.md` |

推荐先拆 OpenCode 并锁定版本、代码事实和实机证据，再用其报告支撑 Magic 目标架构和前端蓝图，最后拆 AgentCore 以验证可继承经验和真实限制。最终在技术会议中以能力矩阵对照：OpenCode 已实现能力、AgentCore 经验、Magic 必须补建、当前不支持和仍未知事项。

三套提示词有不同的读取边界：OpenCode 提示词读取 OpenCode 真实代码和必要的项目文档；Magic 目标项目只读取指定的产品入口文档；AgentCore 现有项目只定向读取与架构/前端相关的历史文档和真实代码，不读取 Magic 产品目录，也不替 Magic 做产品裁定。
