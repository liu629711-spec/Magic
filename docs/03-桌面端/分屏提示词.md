# Magic 桌面端分屏提示词（截图 + LLM → HTML 原型）

**本版变化（2026-09-14）**：每屏配了**现状截图**（存于本目录 `参考截图/`，来自真实运行的 Magic web 形态）和**保留/改进指令**。用法：在 ChatGPT 里**先传截图、再贴提示词**，一屏一条。

---

## 使用说明

1. **同一个 ChatGPT 会话**：先贴【屏 0】通用底座，然后按顺序一屏一屏来。每条消息 = 上传该屏的参考截图 + 贴该屏提示词。
2. **换新会话时重贴屏 0**。
3. **没有截图的只剩两处**：划选注释浮层（合成输入无法触发真实选区事件）、桌面系统通知（桌面专属）。这两处按提示词从零画。其余状态均已用真实运行截取（2026-09-14 实跑补齐）。
4. 也可以整段贴给 v0.dev / Lovable / Motiff AI 生成 React 版。
5. 产出按 `01-shell.html`、`02-agent-session.html` 命名存进 `docs/03-桌面端/prototypes/`。

## 屏 0 · 通用底座（每个会话先贴这一条，不带截图）

```text
你是一名资深桌面应用产品设计师兼前端工程师。我们要为一款名为 Magic 的 AI 工作台设计桌面端界面。我会分屏给你需求：每条消息我会先给一张"现状截图"（当前 web 形态的真实样子），再给该屏的设计要求。截图定义现状，提示词定义契约和改进方向。

【产品背景】
- Magic 是建立在 Agent 执行底座之上的 AI 工作台：用户用自然语言交代目标，AI（Agent）直接干活；复杂任务时主 Agent 以"CEO 方式"组织多个成员 Agent 分工协作、统一交付。
- 两种工作方式：代理（主 Agent 直接执行）/ CEO（组织成员协作）。会话是主要工作现场。
- 桌面端形态 = 桌面壳 + 现有 web 客户端的进化，不是从零发明的全新产品。截图里已有的布局骨架（左导航 / 会话流 / 右侧栏 tab / 底部 composer）原则上保留。
- 用户是中文用户，所有界面文案用简体中文。

【输出要求】
- 每屏输出一个完整可运行的单 HTML 文件（用 <script src="https://cdn.tailwindcss.com"></script>），面向 1440×900 桌面窗口，不需要移动端响应式。
- 所有数据用写死的、可信的中文示例（不要 lorem ipsum、不要英文占位、不要"敬请期待"假按钮）。
- 图标用内联 SVG 或字符，头像用色块+首字，不引用任何外部图片。
- 静态原型即可：hover/选中态要有，业务逻辑不用实现。
- 每个文件顶部加 HTML 注释：屏号 + 屏名。

【界面语言规范】（违反任何一条即返工）
- 用词统一：会话（不说"聊天/对话"）、任务、运行、产物（不说"输出/结果文件"）、成员（不说"员工/角色"）、拍板（决策请求）、验收、物证、副作用。
- 任务板是只读的：Magic 的画布任务板上不得出现"新建任务""手动完成任务"按钮。
- 任务/成员状态只用这些：执行中、排队、等待、阻塞、已完成、部分完成、失败、已取消、未知。不得出现"草拟、已归档、暂停中"等未实现状态。
- 失败、阻塞、权限拒绝、预算超限、副作用等负面信息必须显式呈现，禁止折叠隐藏或用纯颜色示意。

【视觉基调】（可调整）
以现状截图的浅色工具风为基线进化：信息密度偏高、圆角小、分隔靠留白和细线；主色一个，语义色只用于状态。交互细节参考 OpenAI Codex 桌面版的克制风格。
```
