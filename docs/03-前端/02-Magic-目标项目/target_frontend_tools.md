# Magic 目标前端设计工具助手

## 用途

本工具助手配合 `target_frontend_prompt.md` 使用，服务于 Magic 空项目的目标页面、信息架构、状态、协议和首版体验设计，不是前端代码扫描器。

## 工具能力

| 能力 | 用途 | 规则 |
|---|---|---|
| 产品文档定向读取 | 提取产品不变量、首版范围、明确不做项和待裁定 | 默认只读两份入口文档 |
| 信息架构建模 | 生成页面/路由/作用域/导航/对象映射 | 所有页面均标目标/待建立 |
| 状态与交互建模 | 建立任务、运行、成员、会话、审批和副作用 UI 状态 | 不能把运行终态当任务终态 |
| 目标协议设计 | 定义事件消费、fold/reducer、重连重放和错误模型需求 | 未经核查不得写成底座事实 |
| AgentCore 经验对照 | 提取 SSE、fold、IPC、移动端和契约测试经验 | 仅写参考经验，不写 Magic 现状 |
| 目标依赖图 | 生成页面→组件→状态→API/事件的目标 DAG | 节点标注目标模块/待建立路径 |
| 范围与验收分析 | 生成首版拆分、U-01 至 U-12 前端影响、Go/No-Go 和验收场景 | 未决产品选择交给用户 |

## 使用纪律

- 不读取不存在的 Magic 源码，不生成虚假的组件路径、接口、测试结果或截图。
- 不把 AgentCore 的桌面/移动端/后台/AgentTown 直接当成 Magic 页面；AgentTown 是实验边界时必须单独标明。
- 不读取密钥、token、生产数据和真实用户会话。
- 产品不变量、目标设计、参考经验、待技术核查和待用户裁定必须分栏。
- 只有代码、协议或实验有证据时，才把能力写成现有事实。

## 交付检查

- [ ] Magic 无前端代码的阶段边界已明确。
- [ ] 只读取两份必需产品入口文档，补充文档记录了原因。
- [ ] 页面/路由地图覆盖工作入口、代理/CEO、工程、PM、成员、任务、事实、产物、审批和设置。
- [ ] 任务、运行、成员、会话、审批和副作用状态分离。
- [ ] 六条用户流和加载/空/错误/无权限/断连/部分完成/停止/取消状态可验收。
- [ ] AgentCore 经验与 Magic 目标重建设计分开。
- [ ] U-01 至 U-12 和 Go/No-Go 有前端影响，未决项未被擅自决定。
