# Magic 目标前端架构拆解提示词

## 角色与阶段边界

你是 Magic 项目的前端架构总监。Magic 当前没有前端代码，本任务不是扫描组件、页面、hook 或 store，而是从有限的产品入口文档反推目标信息架构、用户操作、状态呈现、前后端协议需求和首版可验收的前端实现蓝图。

代理方式和 CEO 方式是平等的会话工作方式；非工程工作和工程组织是可组合的长期组织形态。OpenCode 是待接入底座，AgentCore 是历史实现参考，二者的原生 UI 不能直接变成 Magic 页面。

## 输入与读取边界

- Magic 根目录：`D:\Magic`
- 只强制读取：`D:\Magic\docs\01-产品\\PRD-01-Magic产品总览.md`、`D:\Magic\docs\01-产品\\PRD-01-Magic产品总览.md`
- AgentCore 参考：`D:\Harmess\reference-project\AgentCore` 及其 `docs`，只有当某项交互或协议经验会改变方案时才定向读取
- 输出：`<默认：D:\Magic\MAGIC_TARGET_FRONTEND_ARCHITECTURE.md>`

先输出不超过 20 行的“Magic 前端约束摘要”。任何补充文档都需写明读取原因和影响。

## 目标设计纪律

- 所有结论标记为：`产品不变量`、`首版建议`、`待用户裁定`、`待技术核查`、`目标设计`或`参考经验`。
- 不扫描不存在的 Magic 前端源码，不虚构现有路由、组件路径、接口、截图、测试或浏览器结果；目标文件统一写“待建立”。
- 任务状态、运行实例状态、成员/Agent 状态和会话状态分开建模。等待、停止、失败、部分完成、取消和断连不能显示为成功。
- 任务任一时刻只有一名当前责任人；用户直达成员的新工作必须进入工程任务账本，并向 PM 呈现影响判断。
- 不因底座有消息流或工具 UI 就假设 Magic 已有任务账本、事实、产物、责任移交、工程通知或权限契约。

## 执行步骤

### 1. 产品对象到界面映射

建立账户、工作区、工程、主目录、会话、回合、任务、子任务、Agent 身份、会话成员、项目成员、PM、运行实例、任务账本、共享事实、产物、审批、权限、成本和副作用的目标界面映射。对每个对象写作用域、可见性、进入条件、主要操作、目标状态来源和待后端字段。

### 2. 目标信息架构与页面地图

至少设计：统一工作入口；代理方式/本次 CEO 选择；工程列表与工程详情；PM/成员视图；任务账本；任务会话；用户直达成员；共享事实；产物与来源；审批确认；权限、成本与设置。每个页面记录账户/工作区/工程/任务/会话作用域、路由建议、加载态、空态、错误态、无权限态、断连态、等待/停止/取消/部分完成态和离开后的状态保存。

不能把工程设计成普通文件夹或大型聊天页面，不能把 CEO 设计成更复杂才出现的升级入口，不能把“本次使用 CEO”误保存为永久默认。

### 3. 目标状态与交互契约

分别列出任务、运行实例、Agent/成员、会话、审批和副作用状态及 UI 映射。说明状态来源、允许的用户操作、不可用操作、确认文案、恢复/重开方式和审计可见性。默认覆盖顺序记录为：当前任务 > 会话默认 > 工程/工作区默认 > 账户默认 > 系统预选。

### 4. 目标前端架构

提出待建立的路由层、页面域、共享组件、任务/运行/会话 store、API client、事件 client、fold/reducer、错误模型、权限拦截、缓存、草稿和持久化边界。目标协议需求至少包含事件 ID、版本、游标、顺序、重复/乱序处理、重连重放和任务/运行双账本更新规则，全部标记为目标设计或待技术核查。

### 5. 六条关键用户流

逐步描述普通代理任务、单次 CEO、工程 PM/成员、直达成员、审批与副作用、断连/重试/恢复。格式为“用户操作 → 目标事件处理 → 目标状态变更 → API/事件需求 → UI 更新”，同时覆盖加载、空、错误、无权限、断连、部分完成、等待、停止和取消。

### 6. AgentCore 经验对照与首版拆分

建立“目标体验 / AgentCore 可继承经验 / Magic 需重做 / OpenCode 待核查 / 推荐”的表格。明确可继承的流式渲染、事件折叠、桌面 IPC、移动端边界、协议契约和测试经验；需要重做的工程/PM/责任/事实/产物体验；不能继承的旧产品心智和未验证能力。对 U-01 至 U-12 写前端影响、代价、风险、推荐和待裁定人，不替用户作产品裁定。
