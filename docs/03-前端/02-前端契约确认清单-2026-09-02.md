# Magic 前端契约确认清单（2026-09-02）

## 0. 用途与填写方式

- 本清单服务于《Magic 前端技术设计方案 V1》（[01-Magic前端方案-V1.md](01-Magic前端方案-V1.md)）阶段 0 的契约冻结，是过会记录，**不是 PRD**。
- 产品范围问题（单用户/单工程/代理+CEO 入口等）已在《第一版范围确认》收口为 confirmed，本清单不重复确认。
- 填写方式：在"结论"列写 **选定选项编号或修改意见 + 一句理由**；暂不能定的注明预期时间。
- 确认后的回写位置：
  - 产品语义变更 → 回写对应既有 PRD（不新建 PRD）；
  - API/状态语义 → 回写设计方案 §0.6/§6.2 与《后端方案 V1》；
  - 全部阻塞项（第 2 节）有结论后，前端阶段 0 才能宣告契约冻结。

## 4. 后端契约逐条确认（对应设计方案 §6.2）

请后端对以下每条标注 **接受 / 修订（附意见）**：

- [ ] `POST /api/tasks`（创建 Task）
- [ ] `GET /api/tasks?status=&owner=&limit=&offset=`（列表）
- [ ] `GET /api/tasks/{task_id}`（详情，含 attempts 摘要）
- [ ] `GET /api/tasks/{task_id}/attempts`（Attempt 列表，attempt_no 倒序）
- [ ] `GET /api/tasks/{task_id}/attempts/{attempt_id}/events?after_seq=&limit=`（事件查询，含 next_cursor）
- [ ] `GET /api/attempts/{attempt_id}/binding`
- [ ] `POST /api/tasks/{task_id}/attempts/{attempt_id}/cancel`
- [ ] `POST .../attempts/{attempt_id}/resolve`（人工收口）
- [ ] `GET/POST /api/tasks/{task_id}/plan`
- [ ] `GET /api/approvals?status=pending`、`POST /api/approvals/{id}/decision`
- [ ] `POST /api/tasks/{task_id}/complete`（验收收口，服务端校验证据）
- [ ] `GET /api/tasks/{task_id}/artifacts|changeset|test-evidence`
- [ ] `GET /api/tasks/{task_id}/cost`
- [ ] `GET /api/tasks/{task_id}/side-effects`
- [ ] 服务信息（CORS/令牌/manifest 下发，B-4/B-7 决议后定形）

已实现接口（health / 创建 Attempt / reconcile）契约以源码为准，不需要确认；如需变更请单独提出并说明兼容策略。
