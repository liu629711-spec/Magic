# Magic 前端方案 V1

## 1. 目标

前端首先服务三个问题：用户现在能做什么、谁负责、结果是否可信。本文定义用户可见的页面、交互、状态和 API 消费方式。V1 使用 Yew 0.23 + Trunk，将 Rust UI 编译为 WASM 并嵌入 Tauri WebView。界面直接连接 Magic API；OpenCode 原始消息、工具过程和事件可以展开查看，但不能绕过 Magic 的任务、审批和状态层。

首版覆盖代理和 CEO 两种工作方式、单工作区单工程、任务执行、审批、结果验收和未知状态收口。

## 2. 页面结构

### 工作台

- 左侧：工作区、工程、任务和进行中的工作。
- 中央：当前 Magic Session 的对话与执行过程。
- 右侧检查器：任务状态、责任人、当前 Attempt、计划、成本、权限、产物和副作用。

### 工程页

展示工程目标、PM、成员、任务列表、资源、事实、风险和最近交付。工程页不承载完整 transcript，只显示结构化结果和可追溯链接。

### 任务页

展示目标、验收标准、当前责任人、计划步骤、Attempt 时间线、底层证据、产物和未决问题。Task 完成按钮只有在验收证据满足后可用。

### 审批和未知处理

审批卡展示动作、资源、范围、风险、预计成本、有效期和批准/拒绝按钮。`unknown_after_restart` 卡展示已知证据、未知原因和三个明确操作：对账、重新执行、人工标记结果。

## 3. 工作方式

代理模式：用户直接对当前责任 Agent 提出目标，系统创建或复用 Magic Session，并在需要时创建 Task。

CEO 模式：用户明确选择 CEO，前端展示计划和工作包；成员结果以结构化卡片回到 CEO，用户不需要管理底层 OpenCode Session。

模式切换默认从下一轮输入生效。若当前 Attempt 正在执行，前端必须显示影响并要求用户选择继续当前 Attempt 或创建新 Attempt。

## 4. 状态展示

### Task 状态

`待开始`、`准备执行`、`执行中`、`等待验收`、`已完成`、`已阻塞`、`已取消`、`失败`、`已归档`。

### Attempt 状态

`已创建`、`已接纳`、`执行中`、`取消中`、`已取消`、`成功`、`失败`、`重启后状态未知`。

前端同时显示 Task 和 Attempt。底层 OpenCode 返回成功只更新 Attempt 证据，不直接把 Task 变成已完成。

## 5. 数据读取和实时更新

首屏加载顺序：

1. `GET /api/tasks/:id` 获取 Task 当前投影。
2. `GET /api/tasks/:id/events?cursor=...` 获取 Magic 事件账本增量。
3. 建立 Magic 的事件订阅；每收到事件先按事件 ID 去重，再更新本地缓存。
4. 连接断开或服务重启后，使用返回的 cursor 重新读取事件；若服务报告需要对账，展示同步中而不是隐藏内容。

前端不直接使用 OpenCode `/event` 作为唯一数据源。OpenCode 原始事件只在调试/证据面板中显示。

## 6. 核心接口

| 页面动作 | Magic API | 成功后的前端行为 |
|---|---|---|
| 创建任务 | `POST /api/tasks` | 打开任务页并显示责任人 |
| 开始执行 | `POST /api/tasks/:id/attempts` | 显示 Attempt 时间线，保存返回的幂等键 |
| 取消 | `POST /api/attempts/:id/cancel` | 显示取消中，等待终态，不显示撤销成功 |
| 重试 | `POST /api/tasks/:id/retry` | 创建新的 Attempt，保留旧 Attempt |
| 对账 | `POST /api/attempts/:id/reconcile` | 显示对账进度和证据来源 |
| 审批 | `POST /api/approvals/:id/decision` | 更新审批卡和 Attempt 时间线 |
| 计划 | `POST /api/tasks/:id/plan` | 更新步骤、依赖和责任人 |
| 事件 | `GET /api/tasks/:id/events` | 按 cursor 增量加载 |

所有写请求的响应都包含 `request_id`、实体 ID、当前状态和事件序号。网络超时后前端必须使用原幂等键查询，不得盲目再次提交。

## 7. 关键交互规则

- 用户关闭窗口不自动取消 Attempt；再次打开时先读取 Task 和 Attempt，再显示继续观察、对账或重试。
- `unknown_after_restart` 不显示为失败，也不显示为成功。
- 取消后保留已发生的文件变化、命令、费用和外部副作用。
- 预算超限、权限拒绝、资源失联和同步缺口使用显眼的状态卡，不能只写入日志。
- 产物、Diff、事实和副作用必须能从 Task 时间线跳转到来源 Attempt。
- CEO 汇总结果必须标明来源工作包和未完成成员，不以成员“运行成功”替代验收。

## 8. 本版验收

1. 用户可以在工作台创建任务并看到唯一责任人。
2. 开始执行、取消、重试和审批均能在时间线中看到对应 Attempt 和事件。
3. 断开网络后重新打开，界面能通过 Magic cursor 补齐事件。
4. 服务重启后，对未终结 Attempt 显示“重启后状态未知”，并提供对账/重试/人工收口入口。
5. 任务完成页同时展示验收标准、产物、测试证据、费用和未决副作用。

## 9. 不在本版冻结

多人实时协作画布、复杂组织看板、任意无损模式切换、自动合并冲突、跨工程成员借调和完整原始思维展示不在 V1 前端范围内。
