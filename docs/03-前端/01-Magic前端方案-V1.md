# Magic 前端方案 V1

## 1. 产品边界

Magic 是独立桌面 Agent 产品。DSH 负责会话、模型、工具和执行；Magic 负责产品界面、会话管理、工程归属、工作区、产品产出和后续治理。

前端只调用 Magic Local Service，不直连 DSH Web UI、Remote API 或 launch token。Magic 不嵌入 DSH Web UI，也不复制 DSH 的 transcript。

## 2. 默认工作流

用户进入 Magic 后直接处于会话工作区：

1. 点击“新会话”即创建并打开一个 DSH Session；不是创建 Task。
2. 用户在底部 Composer 发送消息，消息投递到当前 DSH Session。
3. Magic 从 `session/follow` 日志读取用户消息、Agent 回复和执行过程。
4. 只有需要独立责任、验收、定时、协作或重试治理时，才在关联会话中创建 Magic Task 和 Attempt。

Task 不是左侧默认导航，也不是普通对话的前置条件。

## 3. 布局与交互

界面以 `DESIGN.md`、`UI mockup/` 和成熟桌面 Agent 的已确认区域映射为准：连续三栏，不做 IDE 布局。

```text
┌──────────────────────────────────────────────────────────────────┐
│ Magic                                           窗口最小化/还原/关闭 │
├───────────────┬────────────────────────────────┬─────────────────┤
│ 会话导航       │ 当前会话                         │ 按需工作区       │
│ 新会话 / 搜索  │ 用户消息在右，Agent 在左          │ 文件/终端/Diff   │
│ 自动化 / 插件  │ Composer + 模型选择               │ 关闭时不切断主区 │
│ 置顶/工程/项目/最近 │                                │                 │
└───────────────┴────────────────────────────────┴─────────────────┘
```

- 左栏：会话分为置顶、工程、项目、最近。仅当前会话使用激活色；悬停显示摘要和置顶操作。工程和项目使用文件夹图标。
- 中栏：对话宽度有稳定阅读范围。当前会话运行时，列表项显示加载状态；用户消息右对齐，Agent 消息左对齐。
- 右栏：是中栏的按需延展工作区，不是独立页面。左右栏可拖动；到临界值自动收纳，收纳按钮固定在各自外侧。
- 顶栏：显示 Magic，不显示“工作”下拉。窗口控制属于连续标题栏。
- 搜索：点击后使用弹窗搜索会话标题和内容，不占左栏常驻空间。

## 4. 会话数据

DSH 是会话与消息的权威来源：

| Magic API | DSH 映射 | 前端用途 |
|---|---|---|
| `GET /api/sessions` | `session/list` | 左侧会话列表 |
| `POST /api/sessions` | `session/create` | 新会话 |
| `GET /api/sessions/{id}/messages` | `session/follow` snapshot | 加载对话 |
| `POST /api/sessions/{id}/messages` | `session/prompt` | 发送输入 |
| `GET /api/sessions/status` | session projection | 执行中状态 |

前端将 DSH `user/message` 渲染为用户消息，将 `assistant/message` 渲染为 Agent 消息。`turn/end` 的 `completed`、`error`、`aborted` 分别驱动成功、失败、取消状态；其他原因不能假装为完成。

## 5. 模型与供应商

Composer 旁的模型入口用于会话级选择：先展示供应商，悬停供应商后在其右侧展开模型菜单，菜单按内容宽度自适应并右对齐。模型选择不应要求用户每次进入设置。

设置页的“模型与供应商”通过 Magic Local Service 调用 DSH 的受鉴权 Remote API：读取红脱敏设置与当前模型目录，保存/修改 `llm-pi-ai` 供应商配置，测试草稿端点的模型发现，并将选择写入当前 Session。API Key 只单向写入 DSH credential store，不能回传、落库或写日志。模型选择器只展示 DSH 当前可路由的模型；没有可用模型时必须诚实展示空态。

## 6. Magic 扩展

Magic 保存只属于自己的元数据，例如置顶、工程和项目归属。它们以 DSH `session_id` 为关联键，不复制底座消息或工具过程。

插件入口属于 Magic 产品界面。V1 可以管理经过批准的 DSH Bundle/Profile；市场展示、安装授权、失败处理和产品说明仍属于 Magic，不能把第三方 DSH 市场直接当作 Magic 插件市场。

## 7. 运行与错误状态

- Local Service 未连接：显示“本地服务不可连接”。
- DSH 无法启动或初始化：显示“DSH 服务未启动或初始化失败”。
- 会话加载失败：保留当前界面与重试入口，不清空已有消息。
- 模型或供应商未配置：说明该会话不能执行，不伪造回复。
- 运行中：会话列表显示加载效果，Composer 和对话流保持可读。

窗口关闭不等于取消会话或 Attempt。恢复后重新读取 Magic 状态与 DSH 会话日志；没有终态证据时，受治理 Attempt 只能进入或保持 `unknown_after_restart`，不能推断成功。

1. 使用用户配置的模型完成真实执行：发送、工具调用、取消、失败、重启后会话恢复。
3. 将会话管理元数据从界面状态接入 SQLite。

## 10. 第一阶段体验优化

### 10.1 目标与依据

本阶段解决当前 Magic 在真实 Agent 执行时的主要体验问题：用户消息被内部事件污染、执行过程被粗糙地堆成多行文本、工具结果难以定位、子 Agent 与普通会话混淆，以及右侧工作区缺少上下文能力。

本阶段的依据有三类：

1. 用户提供的 Codex、Zcode 截图：执行过程使用紧凑的单行摘要，终端、搜索、读取和其他工具都可通过展开查看详情；运行中显示实时状态，完成后默认收起过程。
2. 已有研究记录：`docs/research/界面布局对照-2026-09-03.md`、`docs/research/会话管理对照-2026-09-04.md`。Claude Code、Codex 和 Zcode 都将聊天、任务/会话和当前上下文工具分层处理，没有把底层生命周期事件直接作为聊天内容。
3. DSH 真实源码：`TurnProcessNodeView` 将已完成回合压缩为一个可展开摘要；`ReasoningRow` 将推理作为独立可折叠行；`ToolRow` 按终端、读取、搜索、Diff、网页等工具类型提供专用展开内容；技能也使用同样的摘要行模型。对应源码位于 `reference-project/deepseek-harness/packages/client/ui-chat/src/client/chat/TurnProcessNodeView.tsx`、`ReasoningRow.tsx` 和 `reference-project/deepseek-harness/packages/client/ui-tool/src/client/tool/components/ToolRow.tsx`。

本阶段不承诺复制 Codex、Claude Code 或 Zcode 的全部功能，不新增未经 DSH 和 Magic PRD 支持的对象。视觉顺序为：先修正事件和信息层级，再实现展开交互，最后补齐右侧工作台。

### 10.2 统一信息层级

Magic 的会话界面固定为四层：

1. 用户消息：只显示真实用户输入。
2. Agent 回复：显示最终 Markdown 正文，以及确实需要用户处理的询问、权限、失败和重试。
3. 当前回合过程：运行时显示，完成后合并为一个过程摘要；推理、工具调用、技能、上下文注入和压缩都属于过程，不是用户消息。
4. 当前会话上下文：工作区、变更、终端、浏览器、文件、来源、子 Agent 和摘要等通过右侧工作台按需打开。

以下内容禁止继续直接渲染为聊天消息：`turn/start`、`step/start`、`step/end`、`turn/end`、内部 `job/*`、未经整理的 `goal/*` 和 `plan/*` 生命周期事件。它们只用于计算状态、排序、过程边界和审计信息。

### 10.3 会话过程展示规则

#### 运行中

- 用户消息发送后立即显示一条进行中的回合过程行，带实时状态和耗时。
- 推理显示为一条可展开的“思考”行，持续更新最后一行摘要；不逐个 Delta 生成多条消息。
- 每次工具调用显示为一行：工具图标、动作名称、一行摘要、运行状态。
- 工具行默认只展示摘要；鼠标悬停显示可展开 affordance，点击整行展开详情。
- 子 Agent 只在主会话中显示一条任务行，不复制子 Agent 的工具过程。
- 用户可以在运行期间停止，或按既有会话规则排队/追加消息。

#### 已完成

- 最终 Agent 回复保持正常展开并作为主要阅读内容。
- 推理和工具过程默认折叠成一条回合摘要，例如“已完成 · 3 个工具调用 · 1 个子 Agent”。
- 没有可计数过程时显示简短的思考摘要，不显示“回合开始”“步骤完成”“回合完成”等协议字样。
- 点击回合摘要后展开该回合的过程；再次点击收起。
- 过程展开状态只影响当前视图，不改变日志和事件事实。

#### 工具行摘要与详情

统一采用“摘要行 + 专用详情”的结构：

| 工具类型 | 摘要行 | 展开详情 |
|---|---|---|
| 终端 / Shell | `已运行 <命令摘要>` 或 `运行了命令` | Shell 标题、完整命令、标准输出、错误输出、退出状态和滚动区域 |
| 搜索 | `查阅 · N 个文件` | 搜索命令、命中文件、匹配片段和可继续展开的结果 |
| 读取文件 | `读取 <文件名>` | 文件路径、代码窗口、行号和打开文件入口 |
| 编辑 / Diff | `修改 <文件名>` | 文件列表、统计、Diff 视图和审查入口 |
| 浏览器 | `打开 <页面摘要>` 或 `查看可用浏览器与标签` | 页面/标签内容和跳转右侧浏览器入口 |
| 技能 | `使用 <技能名>` | 技能结果、失败原因和相关来源 |
| 子 Agent | `派发给 <Agent名> · <任务摘要>` | 只跳转右侧子 Agent 会话，不在主回合内复制完整 transcript |

摘要必须单行、可截断、不撑高布局；详情区域可以滚动。终端输出不能被拼接成主会话的一长段 JSON 或原始事件文本。

### 10.4 上下文、技能和压缩展示

- Agent preset、权限模式和模型选择是会话配置，不作为每条消息旁边的常驻过程行。
- 技能调用作为工具/能力行展示，采用与工具行相同的运行、成功、失败和中断状态。
- 上下文注入只有在影响用户理解、需要审批或需要审计时显示，默认收起。
- 上下文压缩作为一条可展开的系统过程记录，摘要包含压缩发生时间和影响范围；展开后查看压缩前后摘要，不展示原始内部提示词。
- 手动压缩命令和对应的压缩结果需要关联为一个过程节点，不能拆成两条互不相关的聊天消息。
- 摘要/上下文入口放在主会话顶部或会话工具区，打开右侧上下文视图；不增加“向任务补充要求”输入框。

### 10.5 子 Agent 与普通会话的边界

本阶段保留两种不同语义：

1. 当前主会话派发的子 Agent：按 `parentSessionId` 加载，只在当前主会话的任务入口和右侧“子智能体”工作区出现；后台继续运行。一次性子 Agent 只读，continuable 子 Agent 才显示对话输入框。消息和停止操作分别使用 DSH 的子 Agent 专用投递与 interrupt 能力。
2. Agent 创建的独立新会话：是工作区中的普通根会话，进入左侧会话列表，可独立打开和继续对话。可以保留创建来源关系，但不能把它渲染成当前会话的子 Agent列表。

主会话中的子 Agent任务行固定为一行，内容为状态、Agent 名称、任务摘要和当前状态。右侧子 Agent页使用任务列表和选中会话详情两层结构，不使用三行卡片，也不把所有过程塞进主会话。

### 10.6 右侧上下文工作台

右侧工作区属于当前主会话，关闭右侧不影响会话和后台运行。顶部是固定位置的已打开标签，标签内容跟随当前主会话切换，不跨会话串线。

第一阶段支持以下入口和打开规则：

| 入口 | 作用 | 默认打开方式 |
|---|---|---|
| 变更 / 审查 | 查看当前工作区变更、Diff、测试和审查状态 | 当前会话的右侧标签 |
| 终端 | 查看 Agent 已运行命令和当前工作区终端 | 工具行可直接打开对应终端详情 |
| 浏览器 | 查看 Agent 打开的页面和标签 | 工具行或上下文目录打开 |
| 文件 | 查看读取文件、产物和已打开文件 | 文件工具行可跳转 |
| 侧边聊天 | 当前会话的临时辅助聊天 | 独立标签；关闭应用后不承诺持久化 |
| 子智能体 | 当前主会话的子 Agent列表和详情 | 点击主会话任务行自动切换 |
| 来源 | 当前回复或工具结果关联的来源 | 从回复、搜索或来源入口打开 |
| 摘要 / 上下文 | 会话摘要、工作区、模型、权限、上下文使用和压缩记录 | 从主会话摘要入口打开 |

右侧不能继续只有“执行 / 文件”两个混合区，也不能把终端、文件、子 Agent 和后台任务放到同一个无类型列表中。每类内容使用自己的 renderer 和状态；已打开内容以标签保留，未打开的子 Agent仍由后台状态订阅驱动。

### 10.7 分批实施任务

#### 批次 A：事件投影和过程模型

- 重写 `apps/desktop/frontend/src/main.rs` 的 `conversation_messages()`，区分用户消息、Agent 正文、回合过程、工具调用、工具结果、权限、错误和子 Agent任务。
- 建立按回合聚合的过程模型，配对工具调用与工具结果，保留序号、时间、运行状态和错误原因。
- 增加 DSH `turn/end`、工具、技能、压缩和上下文事件的 fixture 测试。
- 验收：发送一次任务后，主会话绝不出现由内部事件伪造的用户消息；完成后过程只显示一个摘要。

#### 批次 B：聊天过程 renderer

- 把当前文本化的 Reasoning、Tool、ToolResult、Status 渲染改为统一摘要行。
- 终端、搜索、读取、Diff、浏览器、技能分别提供详情视图；详情内容只在展开或跳转时加载。
- 增加运行中、成功、失败、中断、等待权限和等待输入状态。
- 验收：悬停能识别可展开行，点击能展开完整详情；终端输出、命令、技能和压缩记录均可追溯。

#### 批次 C：子 Agent 关系和右侧 Agent 工作区

- 使用现有 `subagents/list`、`subagents/prompt`、`subagents/interrupt` API 封装，按父会话维护子 Agent catalog。
- 从左侧普通会话渲染中过滤当前主会话的子 Agent。
- 主会话增加固定单行子 Agent任务入口；右侧增加子 Agent列表、选中会话详情和后台状态更新。
- 验收：关闭右侧后子 Agent继续运行；切换主会话后右侧只显示新主会话的子 Agent；一次性和 continuable Agent 的输入能力不同。

#### 批次 D：右侧上下文工作台

- 将 `WorkspaceTool` 从执行/文件二值状态改为可扩展的工作台标签状态，至少覆盖变更、终端、浏览器、文件、侧边聊天、子智能体、来源和摘要/上下文。
- 为每个标签维护当前会话作用域、打开对象和关闭行为；调整宽度和收起按钮保持稳定位置。
- 工具行、回复来源、文件和子 Agent任务都能打开或切换到对应标签。
- 验收：右侧多个标签可以并存；切换主会话不会显示前一个会话的标签内容；右侧关闭不影响主会话运行。

#### 批次 E：会话配置和管理修正

- 让新会话继承已确认的默认模型，只有用户主动切换时才进行会话级覆盖。
- 完成归档入口与恢复操作，归档会话不混入普通列表。
- 完成插件点击后的详情/创建会话/跳转闭环。
- 修正标准模式、PTC、权限模式的错误映射和可理解的失败提示。
- 验收：新建会话不要求重复选择模型；归档会话可恢复；插件和模式入口不会出现无响应或泛化错误。

### 10.8 第一阶段验收顺序

1. 真实 DSH 模型执行一个包含推理、终端、文件读取、搜索和最终回复的任务。
2. 验证运行中过程实时更新，完成后只保留最终回复和一个折叠过程摘要。
3. 展开终端、搜索、文件读取、技能和压缩条目，确认详情、输出、状态和错误均来自真实事件。
4. 让主 Agent 派发一个一次性子 Agent和一个可继续对话的子 Agent，验证两者在右侧的展示和输入差异。
5. 关闭右侧、切换主会话、重新打开应用，确认后台运行、会话范围和过程恢复正确。
6. 验证变更、终端、浏览器、文件、侧边聊天、来源和摘要/上下文标签可以按当前会话打开，不出现跨会话内容。
7. 验证归档恢复、插件跳转、模式报错和默认模型继承。

本章节完成前，不继续扩展新的视觉装饰或新的一级导航；先通过事件、布局、展开行为和真实 DSH 验收，再处理颜色、图标和细节动效。

## 11. Codex 级会话体验实施契约

### 11.1 目标定义

本节是前端实现契约，不要求复制 Codex 的代码或底座 UI；目标是达到同等级别的体验质量：

- 结果优先：用户先看到本轮完成内容、状态、用时、验证结果和影响范围；
- 过程可解释：执行记录默认收起，展开后按语义和时间呈现真实操作；
- 证据可下钻：命令、文件、Diff、图片、浏览器、技能、审批和子 Agent 都能进入对应上下文；
- 变更可审查：本轮文件改动在消息过程、回合改动区和右侧审查中使用同一份事实；
- 状态诚实：没有真实事件、引用或安全操作能力时，不显示伪造的内容或可点击的假入口。

“Codex 级”指信息架构、密度、响应性、展开体验、可追溯性和工作台联动达到成熟 Agent 产品水准，不代表展示完整原始思维链。产品只展示受控的执行叙事、工具状态和验证证据。

### 11.2 固定页面结构

每个用户 Turn 只能形成一组稳定的回合记录：

```text
用户目标 / 附件
    ↓
回合状态条：完成状态 · 用时 · 操作统计 · 验证状态
    ↓
Agent 交付正文：结果、主要改动、验证、风险和下一步
    ↓
本轮改动：文件统计、逐文件入口、审查入口
    ↓
执行记录（默认收起）：读取 / 搜索 / 编辑 / 命令 / 图片 / 浏览器 / 技能 / 子 Agent / 审批
```

用户消息只显示用户真实输入；重试产生的重复输入必须折叠到同一回合。`turn/start`、`step/start`、`step/end`、`turn/end` 和内部上下文事件不能单独成为聊天消息。

### 11.3 回合状态条

状态条是整个回合过程的唯一总开关，完成后默认收起过程：

| 状态 | 默认文案结构 | 必须行为 |
|---|---|---|
| 运行中 | 正在执行 · 已完成 N 项 · 当前动作 | 实时更新，允许停止，保持滚动稳定 |
| 已完成 | 已完成 · 用时 · 工具数 · 文件数 · 验证状态 | 点击展开过程，失败证据不能隐藏 |
| 失败 | 执行未完成 · 失败原因 · 已完成部分 | 错误摘要常显，详情可展开，可重试 |
| 等待审批 | 等待你的确认 · 动作和影响范围 | 审批原因和操作常显 |
| 已取消 | 已停止 · 已发生的文件、命令和费用 | 不得暗示已回滚 |
| 状态未知 | 暂无法确认执行状态 | 提供对账入口，不得显示成功 |

用时必须由真实事件时间或底座提供的时长计算。缺少时间证据时显示“用时不可用”，不得编造分钟数。

### 11.4 过程记录分组

过程记录按 `ProcessEntry.category` 使用专用行渲染器，不能把所有 payload 转成通用文本：

| 类别 | 摘要示例 | 详情内容 |
|---|---|---|
| read | 已读取 3 个文件 | 文件路径、行范围、打开文件 |
| search | 已搜索 2 次 | 查询、命令、命中和来源 |
| edit | 已编辑 2 个文件 | 文件统计、微 Diff、右侧审查 |
| command | 已运行 4 条命令 | 命令、输出、错误输出、退出码、耗时 |
| image | 已查看 1 张图像 | 缩略图、原图查看、来源 |
| browser | 已访问 2 个页面 | URL、页面标题、快照或截图 |
| skill | 已使用 1 个技能 | 技能名、来源、结果和失败原因 |
| subagent | 已派发 1 个子 Agent | 状态、任务摘要、右侧子 Agent |
| approval | 等待权限确认 | 动作、资源、范围、批准/拒绝 |

连续同类操作允许聚合，但每个子项必须保留稳定的 `event_seq` 或 `call_id`。命令、Diff、图片、浏览器和技能详情不得使用同一个无类型文本模板。

### 11.5 领域模型和关联规则

前端投影至少使用以下概念；具体 Rust 类型可以按现有代码风格命名，但字段语义不能丢失：

```text
TurnRecord
  turn_id, start_seq, end_seq, started_at, ended_at, status
  user_message_id, delivery_message_id
  process_entries, file_changes, verification

ProcessEntry
  event_seq, turn_id, step, call_id, occurred_at
  category, status, title, summary, detail, evidence_refs

EvidenceRef
  kind, stable_id, event_seq, call_id, artifact_id
  file_path, target_url, workspace_target

TurnFileChange
  turn_id, path, operation, additions, deletions
  diff_ref, source_call_id, review_target
```

工具结果必须优先通过 `call_id` 关联工具调用，不能用“最后一条运行中的工具”猜测对应关系。文件变更、终端卡和其他 artifact 必须保留来源事件序号，并能反向定位到回合。

### 11.6 工作台联动

右侧工作台是聊天证据的落点，不是另一份独立日志：

| 触发入口 | 目标 |
|---|---|
| 文件名 / 打开文件 | 文件视图并定位路径 |
| 查看 Diff / 审查 | 当前回合的变更审查并定位文件 |
| 命令详情 | 终端详情并定位命令结果 |
| 图像 | 图像预览 |
| 浏览器行为 | 浏览器标签或快照 |
| 技能 | 技能来源和结果 |
| 子 Agent | 子 Agent 列表与选中会话 |

所有工作台内容必须带当前 `session_id` 和对象稳定 ID。切换会话后不得展示上一会话的选中对象；关闭右侧不得停止会话或后台执行。

### 11.7 分期与边界

- P0：使用现有真实 DSH 事件，完成回合状态条、结果优先布局、过程语义分组、专用命令/文件/状态详情和响应式展开体验。
- P1：补齐回合、工具、artifact 和文件变更的稳定关联；将本轮改动、微 Diff 和右侧审查统一到 `TurnFileChange`。
- P2：在底座提供真实证据后接入图像、浏览器和技能详情；没有证据时保留诚实空态。
- P3：回合撤销不属于 V1 默认能力。只有具备回合基线、变更归属、后续修改检测和冲突处理时才可评估；停止执行不等于撤销已发生副作用。

### 11.8 验收标准

1. 一个包含推理、文件读取、搜索、命令、编辑和最终回复的真实 Turn，只显示一个用户目标、一个 Agent 交付和一个可折叠执行记录。
2. 过程默认收起；展开后能区分读取、搜索、命令、编辑、技能和审批，且实时、成功、失败、等待状态可辨认。
3. 命令详情包含命令、输出和退出状态；失败命令即使过程收起也在回合摘要或验证结论中可见。
4. 文件改动统计只来自真实变更事实；同一文件可从过程项和本轮改动区进入同一审查目标。
5. 没有真实图片、浏览器、技能或撤销能力时，界面不显示伪造缩略图、伪造内容或假操作按钮。
6. 长输出、长路径和长命令不会撑破会话布局；展开区域独立滚动；减少动态效果时仍可完整使用。
7. 重试、取消、审批拒绝、DSH 重启后状态未知和会话切换均保留真实历史，不把失败或副作用包装成成功。
