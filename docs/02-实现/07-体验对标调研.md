## 3. 关键差距详解

### 3.1 通知与后台完成（⑧，缺失，P0）

成熟产品做法：

1. **Claude Code 移动监控**：云会话在 claude.ai/code 跑，手机 app 是监控客户端，`/mobile` 出二维码绑定后推送跟踪（来源：Claude Code Docs《mobile》《web-quickstart》）。
2. **Cursor Slack 集成**：`@Cursor` 在任意频道启动隔离代理，线程内跟进，完成时 Slack 通知（来源：Cursor Docs《Slack》）。
3. **AgentCore「在等你」信号**：只在 turn 因审批/发问/计划审查**停下等用户**时触发通知；进度和完成不算「在等你」；三通道分级（实时事件只送标题、快照兜底、推送仅最后手段）；按设备去重；永不把对话内容塞进通知通道（来源：AgentCore `attention/signal.py`）。
4. **Devin Slack 线程同步**：会话进度按线程回帖，通知可开可关（来源：Devin Docs《Slack》）。

Magic 落地建议：

- **2026-09-13 用户裁定**：产品后续要做成 desktop 桌面端，通知能力**不做浏览器内实现**，整体归入桌面端阶段——原「浏览器 `Notification` API + DSH 事件订阅」方案不采纳。
- 保留为**桌面端通知的设计基线**：两个触发点（「CEO 拍板抽屉挂起等你」「成员任务完成/失败」）、信噪纪律（只送「哪条会话/哪个成员 + ≤120 字标题」、窗口失焦才提醒）、通知点击跳回对应成员工作区。
- 系统级推送 / 移动端：随桌面端形态一并规划，不再单独作为 DSH 上游诉求登记。

### 3.2 决策与审批流：steer 与免重复审批（②，较薄，P0）

成熟产品做法：

1. **Codex steer 态**：responding 时输入框语义切换为「要求后续变更」，发出的消息带「↪ 引导」回执卡片显示在输入区上方（来源：codex-ui `Composer.tsx:66-79,114-128`，该组件库明确还原 Codex 官方 UI）。
2. **Claude Code 权限粒度**：单次允许 / 会话内允许 / 始终允许三档 + Bash 只读命令全模式免提示（来源：Claude Code Docs《permissions》）。
3. **AgentCore ask_user**：「向用户发问」是唯一原语，开场澄清与执行中高成本分叉走同一机制：turn 挂起落盘（`ToolEffect.SUSPEND`），答案经冷恢复路径回注循环，挂起期间 delegate 结果、已读文件全部保留（来源：AgentCore `tools/builtin/ask_user/__init__.py`）。
4. **Hermes 分层审批**：审批阈值/地板/等待分模块治理（`tools/approval_floors.py`、`approval_smart.py`），低风险操作自动放行。

Magic 落地建议：

- **steer 输入态（Magic 层可独立做）**：CEO 会话 responding 时，拍板抽屉输入区切「引导」态；消息走官方信箱（半改道已接好打断通道，见 `docs/02-实现/05-CEO派活改道映射.md`），UI 只需补状态切换 + 引导回执。
- **审批粒度（需 DSH 上游协同）**：「本会话允许」依赖 DSH 审批会话语义；Magic 可先在 Magic 工具（devtools/git_ops 白名单、export）内部实现记住本次选择的效果，不动 DSH 协议。
- **拍板抽屉 → ask_user 语义对齐（Magic 层）**：把「开场澄清」与「执行中分叉」统一到同一拍板卡片形态（参考 AgentCore 单原语设计），避免两套交互。

### 3.3 任务进度可视：折叠体系（①，较薄，P0）

成熟产品做法：

1. **Codex 轻量摘要行**：连续工具调用折叠成一行「已探索 3 个文件 已编辑 1 个文件」，点击展开逐条明细，运行类明细再展开看 shell 输出与退出码（来源：codex-ui `MessageList.tsx:141-225,295-366`）。
2. **Codex turn 折叠**：一轮结束收成「已处理 2m15s」可展开块，中间过程默认藏起，只留最终回答（来源：codex-ui `MessageList.tsx:227-284,602-668`）。
3. **处理中计时**：「正在处理 12s」shimmer 头 + 打字机流式，让等待有温度（来源：codex-ui `MessageList.tsx:445-516`）。
4. **Claude Code plan mode**：先只读探索产出可批准的计划文件，批准后才动手（来源：Claude Code Docs《permissions》plan mode）。

Magic 落地建议（**Magic 层可独立做，纯客户端渲染**）：

- 在 `magic-ceo-ui` 客户端对会话事件流做同款分类折叠（explore/edit/search/run 四类 + 「正在/已」前缀），映射 DSH 工具名即可，不需要改 DSH。
- 成员工作区右侧栏顶部给「正在处理 Ns」计时条；长会话窗口化加载（codex-ui 默认 60 条、上滑加载 40 条，`MessageList.tsx:30-32`）。
- 计划呈现继续用 DSH `ui-plan`，CEO 波次（wave）映射为步骤序列展示。

### 3.4 多成员可视：聚合进度与多方案比较（③，较薄，P1）

成熟产品做法：

1. **Cursor 多代理界面**：8 个代理并行、worktree 隔离、单界面集中 diff 审查；2.2 自动评判推荐最优（来源：cursor.com/blog/2-0 及 2.2 更新）。
2. **Manus Wide Research**：任务可拆则自动拉起上百子代理，网格化呈现各自进度（来源：manus.im/docs/features/wide-research）。
3. **Codex 云端并行任务**：多任务各自出 PR，集中列表看进度（来源：openai.com/codex）。

Magic 落地建议：

- **成员进度聚合（Magic 层可独立做）**：画布节点已能点进成员工作区；再补一个「波次总览」条——每个成员一行（状态/当前动作/最后产出时间），数据来自官方任务板 + 信箱事件，不需要新协议。
- **多方案比较（Magic 编排策略，Magic 层）**：CEO 对高风险波次可对同一任务派 2-3 个成员跑，完成后并排 diff/产出对比 + CEO 评判（可借鉴 Cursor「自动评判」话术与 AgentCore `runtime/debate/` 的对抗评审结构；辩论全套后置）。

### 3.5 记忆透明度：citation 块（⑤，较薄，P1）

成熟产品做法：

1. **Codex 记忆引用块**：assistant 正文中的记忆 citation 被剥离，渲染成「N 条记忆引用」可展开块，每条带文件路径/行号/备注（来源：codex-ui `memoryReferences.ts` + `MessageList.tsx:518-574`）。

### 3.6 输入增强：选中引用与行内评论（⑥，较薄，P1）
