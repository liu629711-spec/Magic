## 1. 插件骨架约定（照抄，别改）

### 1.1 目录结构

```
plugins/magic-<name>/
├── package.json          # 插件元数据 + 脚本
├── cordis.patch.yml      # 自我 insert（DSH 加载入口）
├── src/
│   ├── index.ts          # 插件入口：name / inject / apply
│   └── *.ts              # 内部模块
└── tests/
    └── *.test.ts         # node --test 直跑
```

### 1.2 `src/index.ts` 入口三件套

```ts
export const name = 'magic-<name>'          // 必须与目录名一致
export const inject = ['<服务名>', ...]      // Cordis 依赖服务；缺失则插件不激活
export function apply(ctx: MagicContext): void | Promise<void> { /* ... */ }
```

**依据**：`plugins/magic-ceo/src/index.ts:53,63`、`plugins/magic-work-mode/src/index.ts:1-3`。

> **注意**：`inject` 用的是 Cordis 服务名（如 `'tools'` / `'subagents'` / `'storageDomain'`），不是包名。DSH 侧通过 `domainCtx.provide('storageDomain', facility)` 注册（`storage-domain/src/index.ts:217`）。

### 1.3 `package.json` 模板

```json
{
  "name": "@magic/dsh-<name>",
  "version": "0.1.0",
  "private": true,
```

**硬约束**：`dependencies` 必须为空。V1 内核零依赖（见 `02-V1并行开发计划.md` §2.1）。**不要执行 `pnpm install`。**


**依据**：`plugins/magic-ceo/cordis.patch.yml`。新增插件时，`patches/web.patch.yml` 由**主代理**统一追加，子代理不得改。

### 2.1.2 交付契约语义（`magic-ledger` ↔ `magic-ceo`，2026-09-11 接线确立）

契约不是"验收时才读的配置"，是一条**闭环**，四步缺一不可：

| 步 | 在哪 | 产物 |
|---|---|---|
| 1 声明 | CEO 在 `ceo_delegate` / `ceo_replan` 的任务上写 `contract` | 任务携带 `contract` |
| 2 **告知** | `wrapMemberPrompt` 把契约**要求面**写进 worker 提示词 | worker 知道要交什么 |
| 3 记录 | worker 调 `ledger_record_evidence` 落结构化物证 | 账本 `evidence` 表 |
| 4 判定 | CEO 验收时 `ledger.verify(runId, runId, ground)` | 否决或接受自述 |

**两条硬规则（都有源码依据，违反会静默失效或连锁故障）**：

1. **第 2 步不可省。** 契约只在账本里存着，worker 是看不到的 —— 不把 `required_sections` /
   `artifacts` 写进提示词，worker 无从生产这些章节，契约**永远无法满足**。
   CEO 侧按 `delivery.ts` 的 `contractBrief()` 读取要求面，字段回落口径必须与账本
   `normalizeContract()`（`plugins/magic-ledger/src/contract.ts:63`）一致，否则"告诉 worker 的要求"
   与"账本判的要求"会不是同一套。

2. **默认契约必须是"软"的（不带任何要求）。**
   依据：`unverified` 属于失败集 —— `plugins/magic-ceo/src/wave.ts:14`
   `FAILED = {failed, skipped, cancelled, unverified, unknown_after_restart}`，
   而 `unverified` 会让下游节点被 `skipped`（`wave.ts:129-130`）。
   所以若默认契约带要求，一个漏交物证的 worker 会**连累整条下游链**。
   默认契约（`delivery.ts` 的 `DEFAULT_DELIVERY_CONTRACT`）只承担一件事：
   让 worker 知道要交物证。空要求契约恒为 `satisfied`，不可能改变任何验收结论。

**契约枚举与生效点**：

| 契约面 | 缺省 | 生效方式 |
|---|---|---|
| `required_sections` | 空 ⇒ 不校验章节 | 物证 `sections_produced` 必须含全部名字（精确匹配，不读自由文本） |
| `artifacts` | 空 ⇒ 不校验产物 | 仅 `form='files'` 且**调用方真的给了落盘事实**时校验（见下） |
| `form` | `prose` | `files` 表示"用"，产物必须落盘 |
| `citation_mode` | `''` | `two_phase` 时物证引用必须落在已核验集内 |
| `strict` | `false` | **当前不影响 CEO 判定路径**（`evidenceRejection` 不读它），预留 |

**"无法核对" ≠ "不达标"**：`landedPaths` 传空表示本批未做真实落盘核对，
此时 `missingArtifacts` 不参与否决（`plugins/magic-ceo/src/delivery.ts` 的 `evidenceRejection`）。
否则开了 files 契约会让所有交付集体误伤。真实 fs 核对尚未接入，属已知缺口。

### 2.2 新增能力：存储域（W1/W2/W3 都要用）

```ts
/** 校验器：只需 `.parse`。DSH 运行时只调这两个方法。 */
export interface ValueSchema<T> {
  parse(value: unknown): T
}

/** 域声明。手搓构造，不用 DSH 的 defineDomain。 */
export interface MagicDomainSpec {
  readonly name: string                                  // 必须匹配 /^[a-z][a-z0-9_]*$/
  readonly version: number                               // 非负整数
  readonly layout?: 'single' | 'per-record'              // 默认 single
  readonly global?: { schema: ValueSchema<unknown>; initial: unknown }
  readonly tables: Record<string, { valueSchema: ValueSchema<unknown> }>
}

/** 表句柄。读同步、写持久。 */
export interface MagicTable<T> {
  get(key: string): T | undefined
  entries(): IterableIterator<[string, T]>
  keys(): IterableIterator<string>
  readonly size: number
  put(key: string, value: T): Promise<void>
  delete(key: string): Promise<boolean>
  update(key: string, updater: (current: T) => T): Promise<T>
}

/** 已打开的域。 */
export interface MagicDomain {
  readonly name: string
  table<T>(name: string): MagicTable<T>
  close(): Promise<void>
}

/** 存储端口。 */
export interface StorageDomainPort {
  open(spec: MagicDomainSpec): Promise<MagicDomain>
}
```

**DSH 侧对应实现（证据）**：

- `ctx.storageDomain: DomainFacility`（`storage-domain/src/index.ts:35-39`）
- `open(spec): Promise<Domain<S>>`（同上 `:100-156`）
- `Domain.table(name): KvTable<K, V>`（`storage-domain/src/domain.ts:108`）
- `KvTable` 方法集 `get/entries/keys/size/put/delete/update`（同上 `:42-90`）
- 写入语义：**先落盘后改内存**，成功才发 `domain/changed`（同上 `:1-9`、`:307-346`）

**约束**：`spec.tables` 的 `valueSchema` **只需 `.parse`**；DSH 只在 `open` 时调一次（`storage-domain/src/index.ts:121`）。因此我们提供 §3.2 的本地 schema 帮助函数即可，**不需要 zod**。

**约束**：`ctx.storageDomain` 可能不存在（profile 未加载 storage）。端口必须支持注入内存实现（§3.3），让单元测试不依赖 DSH。

## 3. 存储端口：参考实现（W0 冻结件）

参考实放在 `plugins/magic-ceo/src/store/`，供其余工作流**复制约定**（不是 import —— 各插件独立，目录不交叉）。

### 3.1 文件划分

| 文件 | 职责 |
|---|---|
| `store/types.ts` | §2.2 的全部接口 + `ValueSchema` |
| `store/schema.ts` | `schema<T>()` / `magicDomain()` 帮助函数（零依赖校验） |
| `store/dsh-port.ts` | `createDshPort(ctx)` —— 包 `ctx.storageDomain` |
| `store/memory-port.ts` | `createMemoryPort()` —— 测试用内存实现 |
| `store/index.ts` | 统一导出 |

> **允许合并**：文件划分是**参考结构**，不是硬约束。工作流可合并为更少的文件（例如单个 `src/store.ts`，W2 即如此），**只要导出的接口签名与本文逐字段一致**。结构自由，契约不自由。

### 3.2 域与 schema 帮助函数约定

```ts
/** 造一个只有 .parse 的校验器。 */
export function schema<T>(parse: (value: unknown) => T): ValueSchema<T>

/** 直通校验器：不校验，仅做类型断言（V1 默认，登记为后续升级点）。 */
export function passthrough<T>(): ValueSchema<T>

/** 校验并归一化域声明，镜像 DSH defineDomain 的检查（照 spec.ts:87-114）。 */
export function magicDomain(spec: MagicDomainSpec): MagicDomainSpec
```

`magicDomain` 必须复刻的校验：

1. `name` 匹配 `/^[a-z][a-z0-9_]*$/`（`UNIT_NAME_RE`，`storage/src/backend.ts:10`）；
2. `version` 是非负整数；
3. `layout` 若是则必须是 `'single' | 'per-record'`；
4. 每个表名匹配同一正则；
5. 若声明 `global`，其 `schema.parse(null)` **不得成功**（null 是"从未写入"哨兵，`spec.ts:107-112`）。

### 3.3 端口约定

| 适配器 | 用途 | 行为 |
|---|---|---|
| `createDshPort(ctx)` | 生产 | 转发到 `ctx.storageDomain.open(spec)`；`ctx` 缺 `storageDomain` 时抛清晰错误 |
| `createMemoryPort()` | 单元测试 | Map 实现，语义对齐：读同步、写 Promise、`update` 串行、`delete` 返回是否存在 |

**为什么必须有内存实现**：`plugins/*/tests/*` 不加载 DSH（§2.6）。内存端口让所有业务逻辑可测，DSH 端口由 W5 升级体检验证。

### 3.4 生命周期约定

- 域由**唯一插件**打开并持有句柄；
- 关闭走插件自己的 `ctx.effect` disposer（DSH 要求：调用方拥有句柄生命周期，`storage-domain/src/index.ts:92-96`）；
- 插件卸载时 DSH 会兜底 `closeAll()`（同上 `:210-215`）。

**`ctx.effect` 的真实语义（2026-09-11 实测踩坑，务必照抄写法）**：

```ts
// ✅ 正确：setup 立即执行，其返回值才是 disposer
ctx.effect(() => () => { void domain.close() })
// ✅ 同样正确（官方 storage-json 写法）：setup 里做事，再 return disposer
ctx.effect(() => { const off = register(); return async () => { off(); await close() } })
// ❌ 致命：setup 立即执行 ⇒ 域被当场关闭
ctx.effect(() => { void domain.close() })
// ❌ 致命：把 disposer 本身当 setup 传 ⇒ 同样当场作废
ctx.effect(dispose)
```

依据：`storage-json/src/index.ts:111-117`、`message-feedback/src/index.ts:176-180` —— 两处官方用法都是 `effect(setup)`，且 setup **必须**立即执行（否则 backend 根本注册不上）。

**踩坑记录（三类问题都在真实 DSH 中实测暴露，而 208 个单元测试全部漏检）**：

1. **`inject` 漏声明**：TS 类型里加了 `storageDomain` 却没写进 `export const inject` ⇒ 运行期
   `cannot get property "storageDomain" without inject`，插件整棵树加载失败。
2. **`effect` 传错**：见上 ⇒ 域被当场关闭，表现为 `open` 永不就绪、写队列空转。
3. **工具缺 `output` 声明**：`ctx.tools.register({ name, description, parameters, execute })` 少了
   `output: { schema, render }` ⇒ 加载期 fatal：
   `tool "magic_memory_search" must declare output { schema, render, presentationMeta? }`。
   **`magic-memory` 的两个工具都踩了这个坑**（`magic-ledger` / `magic-ceo` 的工具写法可作范本）。

⇒ **护栏**：单元测试直接调 `apply`、不走 Cordis DI，也不会触发工具注册校验，且 `--dump-config`
只解析配置不 import 包，**这三类问题都只能靠真实加载发现**。凡是动了 `ctx` 用法
（inject / effect / 服务访问 / `tools.register`）的改动，必须在真实 profile 里启一次再收工（见 §5）。

| 插件 | 域名 | 说明 |

| `magic-ceo` | `magic_ceo` | 团队图 / 计划 / 成员 / 用量 / 驻留 |

**硬约束**：单域名单次 open（`storage-domain/src/index.ts:101-104`）。**禁止两个插件共用一个域名。**

**版本约定**：`version: 1` 起步。schema 结构变更 → 递增版本。注意 DSH **不做迁移**：介质版本与声明不一致会在 open 时 `version-mismatch` 拒绝（`storage/src/backend.ts` 契约）。V1 策略：**变更即升版本 + 手工迁移脚本**（后续工作，先登记）。

**layout 选择**：
- `single`（默认）：整个域一个文档。适合记录少而整的（ceo 计划、成员）。
- `per-record`：每条记录一个文档，适合大、稀疏、可单独丢弃的（记忆、物证）。**选择即锁定**，写进内核。

## 7. 升级体检约定（W5）

**目的**：把"上游改名导致静默失效"变成"升级时立刻报错"。

**落点**：`tools/contract-smoke/**`，在 DSH 源码 checkout 内运行（因为只有那里有真实包）。

**最低要求**：

1. 真实加载当前插件集（`magic-work-mode` / `magic-ceo` / `magic-ceo-ui` + 新增插件）；
2. 校验每个插件 `inject` 的服务在宿主上**确实存在**；
3. 校验 `ctx.storageDomain.open` 能被真实调用并成功读写一条记录；
4. **负向测试**：故意破坏一个契约字段（如把 `storageDomain` 改名）→ 体检必须失败。

**登记**：体检结果与锁定的 DSH commit 一起记录，作为"可持续跟随 DSH 更新"的证据。
