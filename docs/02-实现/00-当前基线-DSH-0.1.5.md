# 当前基线（对齐 DSH 0.1.5-rc.2）

本文是 2026-09-11 用官方 git `origin/master` 重新评估后的**实现快照**。它记录「现在是什么」，不重新定义产品语义。产品语义仍以 `docs/01-产品/PRD-01` 至 `PRD-05` 为准。

证据规则与根目录 `AGENTS.md` 相同：结论必须带项目名、路径和行号；未核实的标「待技术核查」。

命名：`DSH` = `reference-project/deepseek-harness`。CodeGraph 分两套索引：Magic 仓（插件）与 DSH 仓（官方源码）。

---

## 1. 一句话结论

官方仓的**当前提交工作区是完整的**，Magic 五个产品插件**可以挂上去并加载**，但**不能当成「换底座就能原样用」**。官方 0.1.5 的 Agent Teams 是更好的协作地基，不是 Magic 产品的替代品。形态 A'（只挂官方服务 + 面板，不挂官方工具）仍然成立。

## 3. 当前真正加载的东西

`patches/web.patch.yml` 分两层，按序 insert：

**官方层（路径挂载，形态 A'）**

- `agent-team` → `../reference-project/deepseek-harness/packages/experimental/agent-team/lib/index.js`
- `ui-agent-team` → `../reference-project/deepseek-harness/packages/experimental/client-ui-agent-team/lib/index.js`
- **不挂** `tool-agent-team`
- **不挂** `magic-engineering`

**Magic 产品层**

- `magic-work-mode` / `magic-ledger` / `magic-memory` / `magic-ceo` / `magic-ceo-ui`

仓库里还有 `plugins/magic-engineering`，与 PRD-03 暂缓一致，不进 patch。没有 `plugins/magic-consult`。

路径挂载的原因没有变：CLI 只把 experimental 放在 **devDependencies**（`workspace:^`），`profileDependencyNames` 只扫 `dependencies` + `peerDependencies`（`DSH/packages/boot/app-boot/src/profile.ts:460-461`）。`--patch` 不产生 bundle 层，按包名挂会在**运行期** `Cannot find package`；`--dump-config` 不 import 包，查不出这件事。

官方自己的 `agent-team-profile` **会同时 insert `tool-agent-team`**（`DSH/packages/experimental/agent-team-profile/cordis.patch.yml:23-37`）。Magic 不能改用官方 profile 来「顺便升级」，否则模型可见面会被那套 Team 工具改掉。

## 4. 自研插件能不能直接用

**能加载，不能假装契约没变。**

| 插件 | 加载 | 运行时契约 | 说明 |
|---|---|---|---|
| `magic-work-mode` | 可 | 可用 | `inject`: `systemPrompt` / `commands`（host），client 另挂 slots |
| `magic-ledger` | 可 | 可用 | 已在 patch；CEO 用 `ctx.get('magicLedger')` 可选消费 |
| `magic-memory` | 可 | 可用 | 已在 patch；`inject` 含 `magicWorkMode` |
| `magic-ceo` | 可 | **派活仍走 `ctx.subagents`** | `startContinuable` 在 `plugins/magic-ceo/src/index.ts:965`。`readAgentTeams` 只做探测，不改道 |
| `magic-ceo-ui` | 可加载 | **检查器挂空槽** | 见下一节 |
| `magic-engineering` | 未挂 | — | 产品暂缓，不是技术失败 |

鸭子类型仍然有效的部分：

- `PromptAssembleContext.agent.session.id`（`plugins/magic-ceo/src/index.ts:84-91`）对得上 `AssembleContext.agent`（`DSH/packages/core/agent/src/runtime-types.ts:19-21`）。`assembleContextFor` 仍注入 `agent`（`DSH/packages/core/agent/src/dispatch.ts:174-175`）。
- Cordis 服务键 `ctx.agent` 已从 `Context` 去掉，改成 `ctx.agents`（`DSH/packages/core/agent/src/index.ts:26-29`）。Magic **没有** inject `agent` 服务，所以这条删除打不中当前插件。
- `ctx.subagents.startContinuable` 仍在（`DSH/packages/subagent/subagent/src/index.ts:228`）。官方 `spawnTeammate` 自己也调用它（CodeGraph：`roster.spawnAdmitted` ← `startContinuable`）。

### 4.1 已经对不上的两处

**（1）成员工作区 / 检查器**

Magic 客户端假定：

```ts
layout: { openDetails: () => void; closeDetails: () => void }
ctx.slots.inject('details', ...)
```

证据：`plugins/magic-ceo-ui/src/client/register.ts:254`、`:283`、`:300-308`；画布点击走 `props.openDetails`（`CeoTeamGraph.ts:990/995/1107`）。

官方 0.1.5 的 `ILayout` 只有 `selectPanel` / `beginNavigation` / `toggleSidebar` / `openRightbar` / `closeRightbar`（`DSH/packages/client/ui-layout/src/client/service.ts:28-51`）。CodeGraph 查 `openDetails`：**生产符号 0 命中**。根槽位是 `sidebar` / `main` / `rightbar` / `shell.overlay`（`DSH/packages/client/ui-layout/src/client/index.ts:151-155`），右侧是 `rightbar`（`DSH/packages/client/ui-sidebar-right/src/client/index.ts:149-168`）。`openDetails` 只残存在官方**测试替身**里。

后果：CEO 图画布能画；点节点想打开成员工作区时，调用的是不存在的 layout 方法，检查器也挂在已删除的 `details` 槽。这是当前最大的活契约漂移。改它会改交互，**未改代码**。待裁定：迁到官方 `rightbar`，还是在画布内做面板。

**（2）`AgentTeamsPort` 形状过期，且生产路径没用它**

```ts
sendMessage(caller, { target, content, delivery: 'quiet' | 'wakeup', signal })
```

证据：`plugins/magic-ceo/src/index.ts:685-702`。

官方实际是：

```ts
SendTeamMessageRequest = { target, content, signal }  // 无 delivery
```

证据：`DSH/packages/experimental/agent-team/src/types.ts:159-163`；`TeamService.sendMessage` 在 `index.ts:163-165`。

`readAgentTeams` 只检查 `spawnTeammate` / `sendMessage` 是不是函数（`:711-718`），所以探测仍会报 `available`。真正派活仍是 `ctx.subagents.startContinuable` / `sendMessage` / `interrupt`。把 CEO 改道到 `spawnTeammate` **会改产品语义**（官方成员创建后 name/description/context 不可变），未做。

## 5. 官方新能力是不是更好

更好的是**地基**，不是 Magic 的方向盘。

| 能力 | 官方 0.1.5 | Magic | 判定 |
|---|---|---|---|
| 名册 / 驻留 | `TeamService` + Lead Session 事件日志 | `residency.ts` + `magic_ceo` 域 | 官方更强：持久、可恢复 |
| 消息 | 持久信箱，离线排队；`status: accepted \| queued` | `ctx.subagents.sendMessage` | 官方更强 |
| 任务板 | CAS + revision，任务动作闭集 | `plan.ts` / `wave.ts` | 官方适合「谁在跑」；Magic 的波次 / 依赖 / 验收更宽 |
| 模型入口 | `tool-agent-team`：无 parent 的顶层会话默认 lead，挂上后**每个普通会话**都拿到 Team 工具 | `ceo_*`，受工作方式约束 | **官方工具对 Magic 更差**。依据：`tool-agent-team/src/index.ts:397-399` × `roster.ts:92-115` |
| UI | 会话头 `conversation.session.header.actions`（`client-ui-agent-team/src/client/mount.ts:66-74`） | CEO 画布 + 成员工作区 | 互补。官方面板不能 `spawnTeammate`（Remote 只有 view/createTask/updateTask） |
| Session | writer = 3，`latestReleasedVersion: 3`，`evidenceTag: dsh-v0.1.5-alpha.1` | 消费 DSH session | 比旧文案「VERSION 停在 0、无兼容承诺」更硬；已发布数据要相邻迁移 |
| npm experimental | `@deepseek-ai/dsh-experimental-agent-team` 已发 `0.1.5-alpha.2`；五包 `publishConfig.access: public` | 仍路径挂载 | 发布了，但 CLI runtime 闭包仍不含它们，所以挂载方式暂时不变 |

CodeGraph（DSH 索引 5603 files / 62154 nodes / 397687 edges）：

- `spawnTeammate` 的生产调用方只有 `tool-agent-team` 的 `install`（`tool-agent-team/src/index.ts:159`）和官方测试。Magic **不是**调用方。
- `startContinuable` 的调用方包括官方 `roster.spawnAdmitted` 和 Magic `apply`。两边最终都落到同一套 continuable 子代理。
- `ILayout` 的影响面在 `ui-layout` / `ui-workspace` / `ui-sidebar-right`，没有 Magic 假设的 details API。

**结论**：官方 Teams 值得当可靠性底座；官方工具和官方 profile 不能直接拿来当 Magic 产品。账本、记忆、工作方式、CEO 波次、画布，官方都没有对应物。
