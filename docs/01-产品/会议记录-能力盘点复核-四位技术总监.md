# 能力盘点复核：四位技术总监会议记录

## 一、会议目的

对《能力盘点-OpenCode与AgentCore常用能力》进行第二次技术复核。此前复核因 `403 INSUFFICIENT_BALANCE` 未执行，本次重新派发后等待四位技术总监完整返回，再形成汇总结论。

## 二、参会成员

- Magic OpenCode 项目架构技术总监
- Magic OpenCode 项目前端技术总监
- Magic AgentCore 项目架构技术总监
- Magic AI 核心总监

## 三、共同结论

1. 四位总监均完成了主盘点及各自负责领域的技术材料复核，并返回完整正式意见。
2. 主盘点可以标记为 `reviewed`，作为产品、架构、前端和开发会议的防遗漏输入。
3. 主盘点不能直接作为开发冻结批准。版本、协议、对象映射、恢复、权限、副作用和端到端收敛仍需进一步验证。
4. Magic 必须拥有自己的任务、责任、身份、成员、事实、产物、权限和最终状态语义；OpenCode/AgentCore 对象只能作为绑定对象或运行证据。
5. OpenCode 和 AgentCore 的共同能力不能被直接合并成同一种语义。尤其不能把 AgentCore 的 CAPTAIN/worker 直接当 PM/成员，也不能把 OpenCode 的 Session/Run 直接当 Magic 任务。

## 四、必须回写主盘点的修正

### 4.1 OpenCode 领域

- 需要显式盘点完整应用 runtime、独立 V2 runtime、V1/V2/Legacy、generated client 和版本漂移。
- 需要补充输入 admission、排队、steer、去重、并发冲突和按序收口。
- EventV2 durable event、projector、PubSub 和 SSE 必须分开表达；实时连接不自动等于可靠历史账本。
- 文件、Shell、Git、MCP、插件、网络和 Provider 工具都可能产生外部副作用，不能用取消操作承诺自动回滚。

### 4.2 AgentCore 领域

- `Interaction / Turn / Run` 是执行层模型，不是 Magic 的完整任务模型。
- `CAPTAIN` 是回合内编排角色，不自动成为工程 PM；worker、RunSpec 或 transcript 不自动成为长期成员。
- `continue_from_run_id` 是有限的执行现场/上下文续派能力，不等于稳定的会话成员身份复用。
- Journal、Replay、SSE、暂停、恢复和 crash redrive 仍需核查跨进程、跨 worker 和外部副作用边界。
- `success` 可以和 structured gap、partial、degraded 等结果并存，不能直接推导 Magic 任务完成。

### 4.3 前端与产品领域

- 任务状态、运行状态、连接/同步状态、审批状态、产物状态和责任状态必须分开显示和建模。
- 默认界面可以折叠底层工具日志和协作细节，但不得隐藏失败、等待、同步缺口、责任人和已发生副作用。
- 用户直达成员产生的任务必须进入 Magic 任务账本，并处理 PM 感知、优先级和冲突。
- 计划步骤不自动成为正式子任务、Agent 或 OpenCode Run；升级必须有独立责任、交付、验收、等待/重试或依赖理由。

## 五、共同首版边界

### 必须保留或补建

- Magic 独立任务账本和 `TaskAttempt`；
- `AgentIdentity`、`SessionMember`、`ProjectMember` 和 PM 的独立关系；
- 唯一当前责任人、显式移交和最终收口；
- 事件 ID、顺序、幂等、游标、回放和缺口修复；
- 权限、成本、审批和副作用审计；
- 断连、重启、停止、取消、重试、审批恢复和文件/Git/MCP/网络副作用验收；
- 代理、CEO、工程三种组织方式共享的输入、计划、工具、真实交付和诚实终态。

### 可以后置

- 多层 PM、自动团队扩张、跨工程成员调用、复杂多人协作权限、永久在线 Agent、复杂圆桌和多 worker 横向扩展。

### 明确禁止

- `Run == Magic Task`；
- `CAPTAIN == Project PM`；
- `worker == SessionMember/ProjectMember`；
- `SSE/Replay == Magic 产品真相`；
- `approval == 长期组织授权`；
- `resume == 外部副作用回滚`；
- 运行结束、文件存在、工具成功或断连直接等于任务成功。
