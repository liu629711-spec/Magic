# U-05：新一轮工作选择 CEO：外部评估记录

## 一、用户提出的修正

用户明确修正了此前“执行中切换 CEO”的表达：CEO 不是在已经进行中的运行进程里切换，而是在用户发起新一轮工作时选择的工作方式。

同一个会话主 Agent 在代理职责和 CEO 职责之间切换：

- 代理职责下，主 Agent 直接完成用户目标，按需调用协作者；
- CEO 职责下，主 Agent 负责派发临时成员、组织分析和制作、遵守准则、处理审批与审计边界、汇总结果并向用户最终确认。

用户可以直接在对话中要求使用 CEO，也可以在后续新一轮工作中回到代理模式。首次主动建议可以告知用户，用户关闭后不再重复提示。

## 二、外部评估依据与结论

外部评估员此前关于“不要让用户被迫管理责任”“角色与责任分离”“默认渐进披露”的正式评估，与本次修正的核心方向一致。基于这些既有判断，本议题采用以下产品结论；本记录不把底座技术能力当作外部用户验证结果：

审计说明：本次再次委托已在任务系统中完成，但最新回合正文未被系统展开。因此，以下内容依据外部评估员此前已返回的正式评估和用户本次明确方案整理，不把未展开回合冒充为新增的逐条签字意见。

1. 用户是在交代下一件事情时选择“请你直接做”还是“请你组织团队做”。
2. 已经开始的工作不会因为下一条消息被重新解释，减少重复执行和状态混乱。
3. CEO 是当前主 Agent 的一种工作职责，不是突然出现的第二个产品身份。
4. 用户可以看见本轮使用的是代理还是 CEO，但不需要每次阅读完整组织过程。
5. 提示应该是一次性、可关闭的辅助，不应成为每次任务前的表单或弹窗。

## 三、必须保留的边界

### 3.1 模式与进程分离

已经开始的 OpenCode/AgentCore 运行保持原模式和运行事实。后续新输入可以排队，但不能把旧进程、旧运行或旧结果改写成 CEO 运行。

### 3.2 主 Agent 与临时成员分离

CEO 由当前会话主 Agent 承担。临时成员只承担被派发的局部工作，不因为一次 CEO 协作自动获得长期工程身份、跨会话身份或更高权限。

### 3.3 CEO 与权限分离

CEO 可以依据已授权范围组织工作、提出审批和汇总审计，但不自动拥有超出 Magic 权限策略或用户授权的权限。

### 3.4 任务连续性

用户说“继续刚才的目标”时，保持同一 Magic 任务的目标、有效结果、未完成计划和责任关系；用户提出新目标时，建立新的 Magic 任务。模式变化本身不自动新建任务，也不自动修改会话默认方式。

### 3.5 可见但不打扰

首次主动建议可使用一次说明；关闭后不重复主动提示。明确选择 CEO 或代理时不重复确认，但当前回合保留轻量标签，例如“本轮：CEO 协作”或“本轮：代理执行”。

## 四、白话例子

用户先说：

> “帮我修复这个登录问题。”

主 Agent 以代理职责执行，必要时调用临时协作者。运行已经开始后，用户又发送：

> “这次请用 CEO 方式，先让不同成员分析前端、后端和测试。”

这条要求不会改变正在进行的旧运行。旧运行完成或按队列规则结束后，新的工作以 CEO 职责启动，主 Agent 组织临时成员，吸收旧运行的有效结果，但不重复已经完成的内容。

之后用户说：

> “好，接下来你直接帮我把修复做完。”

下一轮回到代理职责。对话目标和已确认结果继续保留，用户不需要重新解释背景。

## 五、正式 U-05 规则

> CEO/代理选择属于新一轮工作，而不是已开始运行的进程内切换。当前会话主 Agent 可以在代理职责和 CEO 职责之间切换；CEO 职责下可派发临时成员，并负责准则、审批边界、审计、汇总和最终用户交付。旧运行事实不被改写，新一轮沿用可用上下文但创建独立运行记录。首次主动建议可关闭，明确选择不重复提示；工作方式变化不自动改变会话默认值。

## 六、仍需技术核查

- 新输入在旧运行期间的排队、接收和运行顺序；
- 同一 MagicSession、MagicTask、Turn 和底层 Run 的具体映射；
- CEO 派发临时成员时的独立上下文、结果回收、取消和复用边界；
- 旧运行有效结果如何安全注入新 CEO 运行，避免重复工具副作用；
- 运行方式标签、审批状态、审计记录和任务账本的事件收敛。

## 七、结论

本议题标记为：**首版采用，技术实现待核查**。
