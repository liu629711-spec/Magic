# U-12 权限模式与审批规则

## 一、正式规则

Magic 前台提供三档简单权限入口：

| 入口 | 用户能理解的含义 |
|---|---|
| 请求批准 | 遇到需要确认的动作时暂停并询问 |
| 当前范围内自动处理 | 在当前任务、会话或工程已授权范围内自动工作，高风险动作仍询问 |
| 完全访问当前工程 | 解除当前工程的文件和网络访问限制，但系统禁止项、高风险确认、预算和账户边界仍有效 |

这三档入口不是完整权限表，也不等于代理、CEO 或工程模式。工作模式决定如何组织工作，权限模式决定哪些动作可以自动执行。

## 二、内部权限维度

Magic 内部必须分别治理：

```text
资源访问边界
审批策略
动作风险
预算范围
环境范围
授权有效期
授权来源
```

底层授权结果继续使用：

```text
allow / ask / deny
```

任何三档前台选择都不能突破上级硬边界、系统禁止项、预算上限或账户边界。

## 三、作用范围

“当前范围内自动处理”默认作用于当前任务。扩展到当前会话或当前工程必须明确显示范围和有效期，不能因为一次点击变成账户永久权限。

“完全访问当前工程”只放宽当前工程的文件和网络访问边界，不自动获得其他工程、其他账户、其他 Agent 私有记忆、原始凭据或生产环境权限。

## 四、动作处理

低风险、可逆且已经授权的动作可以自动执行：

- 读取授权文件；
- 生成计划；
- 使用独立修改空间；
- 创建 Git 分支或工作树；
- 执行本地测试；
- 创建本地提交；
- 在预算内派发低风险子任务。

以下动作由项目策略决定，必要时请求责任人确认：

- 合并主版本；
- 远程推送；
- 修改共享资源；
- 使用新的外部资源；
- 超出原任务范围；
- 超出普通预算但仍可能被批准的动作。

以下动作必须确认或首版禁止：

- 删除重要资源；
- 生产部署；
- 生产数据库或生产 API 写入；
- 付费和购买资源；
- 对外发送消息或公开发布；
- 使用新的敏感凭据；
- 无法可靠审计或可能重复产生副作用的动作。

## 五、运行中审批

运行中遇到高风险动作时：

```text
保存当前结果和运行事实
        ↓
进入等待确认
        ↓
批准后继续，拒绝后保留历史
```

系统必须区分模型建议、Magic 是否允许、底层是否实际执行和外部副作用是否已经发生。恢复任务时不能重复执行已经发生的动作。

## 六、记录要求

权限和审批至少记录：

- 请求主体和任务；
- 目标资源、动作和范围；
- 风险等级、环境和预算；
- 批准主体、批准方式和有效期；
- 底层执行结果；
- 已发生的副作用；
- 拒绝、失败、回退或补偿结果。

## 七、首版边界

首版做三档前台入口、任务级默认范围、`allow / ask / deny`、上级硬边界、预算拦截、审批记录和副作用审计。不做复杂权限矩阵前台、不做一次点击永久放开账户、不做绕过系统禁止项的“完全访问”、不做无法审计的自动生产操作。

## 八、成熟产品参考

以下是产品设计参考，不代表 Magic 已经拥有这些底座能力：

- **Codex**：提供“Ask for approval、Approve for me、Full access”权限入口，并明确区分 Sandbox 访问边界和 Approvals 审批方式；改变审核方式不会自动扩大 Sandbox。参考：[OpenAI Codex Permissions](https://developers.openai.com/codex/permission-modes)。
- **OpenCode**：使用 `allow / ask / deny`，支持按工具、命令和路径细分；自动模式不会绕过明确的 `deny`；一次审批可以只允许本次，也可以在当前会话中继续允许匹配规则。参考：[OpenCode Permissions](https://opencode.ai/docs/permissions/)。
- **Claude Code**：提供 default、acceptEdits、plan、auto、dontAsk、bypassPermissions 等权限模式，并将权限规则、沙箱和自动安全审查分开；显式 `ask` 和 `deny` 可以保留人工检查或硬阻止。参考：[Claude Code Permission Modes](https://docs.anthropic.com/en/docs/claude-code/permission-modes)。

Magic 借鉴的是共同结构：前台选择保持简单，访问边界和审批策略分开，高风险动作保留独立拦截。Magic 仍需通过 OpenCode 实机核查确认底层审批、沙箱、预算和副作用审计的适配方式。
