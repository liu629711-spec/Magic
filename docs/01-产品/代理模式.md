# 代理模式

## 一、产品定义

代理模式是 Magic 基于 OpenCode 提供的直接 Agent 工作方式。用户提出目标，Agent 自主完成理解、计划、执行、检查和修正，用户不需要管理内部任务拆分。

代理模式不是简化版，也不是进入 CEO 模式之前的过渡页。它本身就是一个完整的、高强度的 Agent 工作台。

## 二、用户心智

> **我交代一件事，你直接帮我做。**

用户关心的是目标、过程状态、修改结果和最终交付，不需要先关心 Agent 的内部组织方式。

## 三、核心循环

```text
说目标 → Agent 理解 → 自主执行 → 检查结果 → 继续修正 → 交付
```

Agent 可以在内部进行计划、步骤拆解和工具调用。这些内部动作服务于执行，不自动变成用户需要管理的多 Agent 团队。

## 四、Agent 的自主范围

在用户已授权的范围内，Agent 可以：

- 阅读相关文件和代码
- 自主选择工具
- 拆解执行步骤
- 修改文件
- 运行检查和测试
- 根据反馈修正结果
- 在任务没有完成时继续推进
- 汇报完成、部分完成或失败状态

需要用户做出的关键决定仍然必须被明确请求，例如高风险操作、超出授权范围的行为、目标不明确或存在不可逆后果的选择。

## 五、代理模式中的“派发”

代理模式允许 Agent 为了完成工作进行内部的连续任务安排和工具调度。产品上要区分两件事：

1. **执行层派发**：Agent 为了完成当前目标自动安排步骤、调用工具或推进工作，用户无需管理。
2. **组织层组队**：创建多个具有独立身份、协作关系和可观察任务的 Agent 团队，需要用户主动选择 CEO 模式或工程模式。

代理模式默认执行第一种，不强制进入第二种。

## 六、用户可见内容

默认优先呈现：

- Agent 当前正在做什么
- 重要的文件修改
- 检查和验证结果
- 需要用户决策的事项
- 当前任务是否继续推进
- 最终交付和未完成部分

默认不要求用户处理：

- 每一个内部步骤
- 每一次工具调用
- 内部计划的全部细节
- Agent 是否应该拆成几个小步骤
- 用户不需要知道的底层执行日志

用户可以在需要时展开过程，但“可见”不等于“必须管理”。

## 七、代理模式的升级建议

当任务适合团队协作时，系统可以给出非阻塞建议切换到 CEO 模式。建议必须满足：

- 当前工作不被强制打断
- 当前已完成结果不丢失
- 用户可以选择继续代理模式
- 不把代理模式描述成能力不足
- 不自动创建长期工程团队

## 八、完成标准

代理模式的一次任务只有在以下内容明确后才算完成：

- 用户目标已经得到回应
- 实际执行过的工作有事实依据
- 文件或代码修改已经真实落盘
- 验证结果被如实说明
- 未完成、失败或等待事项没有被隐藏
- 用户知道下一步是否需要介入

## 九、待决策

- OpenCode 原生 Agent 的哪些交互直接复用，哪些需要 Magic 统一包装
- 代理模式是否支持用户保存局部行为偏好
- 代理模式中的连续工作是否需要独立任务面板
- Agent 何时可以主动询问用户，何时应继续尝试
