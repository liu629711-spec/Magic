# 核心对象模型

## 一、目的

本文用产品语言建立 Magic 的对象地图，重点区分工作空间、工程、会话、Agent 身份和任务执行，避免把“调用一次子 Agent”“建立会话团队”和“建立项目长期组织”混为一谈。具体字段、存储和接口属于后续技术设计。

本文是对象词典和概念入口，不重复展开全部状态与异常生命周期。涉及责任、状态、恢复、权限和底座映射时，以《Magic 产品系统边界与生命周期底图》为基线；涉及当前首版取舍时，以《Magic 最终产品裁定与技术会议输入》为准。

## 二、对象关系

```text
用户
├── 账户偏好与角色模板
└── 工作空间
    ├── 普通会话
    │   ├── 会话主 Agent
    │   ├── 会话成员
    │   └── 多个任务与执行记录
    └── 工程
        ├── 项目专属 PM
        ├── 项目专属成员
        │   └── 各自的成员任务会话
        ├── 项目计划、任务与依赖
        ├── 一个默认工作位置与多个资源关联
        ├── 共享信息、产物与文件
        └── 圆桌会议和组织治理
```

## 三、基础范围对象

### 用户

最终目标、范围、关键判断和授权的拥有者。用户可以只与代理工作，也可以采用 CEO 协作，或创建由项目 PM 管理的工程组织。

### 工作空间

Agent 可以访问、修改和交付文件或产物的基础范围。多个会话可以位于同一工作空间，但共享文件不等于共享 Agent 身份、私有上下文或团队关系。

### 工程

围绕一个长期项目建立的持久组织边界。工程拥有自己的目标、PM、成员、任务、共享信息、权限和协作关系。

不同工程默认使用不同的 Agent 实例。两个工程都可以拥有“前端 Agent”，但它们只是来自相同角色模板，不是同一个成员，也不共享项目记忆和任务关系。

### 工程资源与修改空间

工程可以关联多个本地或外部资源。工程的默认工作位置只是用户打开工程或任务尚未明确资源时的入口，不是工程的资源数量上限，也不等于唯一写入位置。

- **资源**：可被工程、任务或运行实例引用和授权的本地目录、代码仓库、文档、URL、数据库、API、设计平台或其他外部对象。
- **工程资源关联**：记录某个工程为什么关联某个资源，以及默认入口、可用动作、范围、版本、成本和副作用边界。
- **执行目标**：一次 TaskAttempt 实际使用的资源版本、目录、Checkout、Branch、Worktree 或其他隔离空间，并记录写入范围和当前主动变更责任主体。
- **变更集**：一次任务对资源产生的文件或对象变化、版本引用、检查结果和来源证据。
- **合并任务**：把变更集检查、解决冲突并纳入目标主版本或正式资源的独立工作。它可以由不同于执行 Agent 和任务责任人的授权主体负责。

代码、文本和配置资源的重叠修改优先使用独立修改空间和 Git 变更；非 Git 资源使用适合自身的快照、版本、锁、草稿、测试环境、审批或补偿机制。任务完成、变更可合并、变更进入主版本和最终验收不是同一个状态。

### 会话

用户或工程成员围绕连续目标进行交流与执行的范围。普通会话拥有会话主 Agent 和可选会话成员；工程成员也可以为不同任务拥有多个独立会话。

### 任务与回合

任务是要完成的一项可执行工作；回合是一次用户或上级 Agent 输入触发的完整执行单元。一个任务可以跨多个回合，也可以包含多个 Agent 的执行。为了支持未来团队画布，任务还必须能够关联派发、执行、结果交付、唯一责任和依赖关系。

运行实例是某个任务或回合的一次实际执行尝试。一个任务可以拥有多个运行实例；运行状态不能直接替代任务状态，也不能隐式改变任务当前责任人。用户已确认首版产品层采用 `MagicSession 1-N MagicTask`、`MagicTask 1-N Turn`、`MagicTask 1-N TaskAttempt` 的分层，并为团队画布预留派发、执行、交付、责任和依赖关系；OpenCode Session/Run 的具体绑定仍需技术映射。

### 任务计划与计划步骤

计划是任务内用于理解、推进和展示进度的轻量结构。较长任务可以由主 Agent 自动生成计划，并向用户展示已完成步骤、当前步骤、下一步和阻塞原因。计划能力适用于代理、CEO 和工程任务，不代表建立团队，也不改变任务的当前责任人。

计划步骤不是 Agent、会话或正式子任务。只有需要独立责任人、独立交付/验收、单独等待/重试/暂停、跨成员依赖或单独追踪时，计划步骤才升级为正式子任务。一个计划步骤可以对应多个运行实例，一个运行实例也可以完成多个计划步骤；计划步骤、MagicTask、TaskAttempt 和 OpenCode Run 不强行一一对应。

## 四、Agent 身份对象

### 会话主 Agent

普通会话中持续面对用户、理解目标并对交付负责的首要 Agent。代理模式下它直接负责执行；CEO 模式下它承担 CEO 职责。工作方式变化不会自动替换会话主 Agent。

### 会话成员

由用户、会话主 Agent、CEO、PM 或获授权成员创建或采用的完整 Agent 会话。会话成员拥有独立上下文、记忆、任务历史和正常 Agent 工具系统；实际权限、项目归属、可见范围和责任来源由成员关系与任务授权决定。它可以在授权范围内读取相关会话、任务、成员汇报和项目事实，也可以创建自己的下属 Agent 会话。

### 项目 PM

某个工程专属的长期管理 Agent。一个工程同一时间只有一名当前 PM，唯一的是工程级最终协调责任，不是唯一 Agent 身份、唯一会话或唯一能提出建议的人。PM 负责理解项目目标、维护计划、建立或调整成员建议、派发任务、协调依赖、汇总进度、组织圆桌和向用户报告。工程可以拥有助手或代理 PM，但它们默认不与当前 PM 同时拥有冲突的正式协调权。

### 项目成员

通过成员关系挂接到某个工程的完整 Agent 身份与会话。项目成员拥有独立上下文、项目范围内的记忆、权限、协作关系和任务历史，可以被用户、PM 或获授权组长持续派发。项目成员的任务角色可以变化，不要求永久绑定“前端”“测试”等固定职业。

### 团队画布

团队画布是工程团队的可视化工作投影。成员节点表示 Agent 身份和工程成员关系，任务节点表示交付目标，会话和回合表示连续交流，运行表示一次执行尝试。画布还要分别显示谁派发、谁执行、结果交给谁、谁负责以及任务依赖谁。它不是 OpenCode Session/Run 的原始拓扑图，也不是第二套任务状态来源。

### 临时执行 Agent

为一次局部工作创建、任务结束后默认不保留成员关系的完整 Agent 会话。它与其他 Agent 使用同一类正常执行、上下文和工具能力；“临时”只表示生命周期、归属、可见范围和责任边界。它可以由会话主 Agent、CEO、PM、组长或项目成员创建，后续也可以建立新的会话成员、项目成员或借调关系。

### 角色模板

用于快速创建默认团队或常见专家的职责、工具建议和行为配置。角色模板不是成员身份，也不是项目必须固定拥有的岗位；CEO、PM 或用户可以不使用模板，直接按当前任务创建“调研专家”“架构专家”等动态角色。模板可以跨工程复用，但不会自动复制成员记忆、权限或责任。

## 五、协作对象

### CEO 职责

CEO 是会话主 Agent 或工程成员在复杂任务中采用的协作组织职责，不等于一个必须永久存在的全局 Agent。承担 CEO 职责的 Agent 负责分工、协调、追踪、综合和交付。

### 会话团队

当前会话主 Agent 与一组会话成员形成的协作关系。团队可以在多个任务中继续存在，并在代理辅助与 CEO 协作之间切换，但归属范围仍是当前会话。

### 工程团队

由项目 PM 与项目成员构成的长期组织。工程团队可以跨本工程的多个会话和任务持续工作，并根据项目阶段增加、调整、停用成员。

### 成员任务会话

项目成员处理某项工作的独立执行空间。一个成员可以拥有多个任务会话。成员身份长期存在，会话则可按任务创建、完成和归档。

### 圆桌会议

工程内围绕议题组织的结构化多人讨论。圆桌由 PM 或获授权成员召集，形成证据、分歧、结论和后续任务；它不是所有任务的固定步骤。

## 六、信息与交付对象

### 记忆

可跨回合或会话使用的信息。至少区分账户偏好、会话成员上下文、项目共享事实、项目成员独立记忆和临时执行上下文。

### 共享信息

在指定协作范围内可被多个 Agent 使用、具有来源和更新责任的信息。共享工作空间中的文件不自动等于所有会话成员都共享完整记忆。

### 产物

Agent 或团队生成并可由用户访问、验证或继续编辑的文件、代码、文档或其他结果。Agent 身份失效或不可跨范围调用，不影响已经交付到工作空间或工程的产物继续存在。

## 七、生命周期与复用边界

| 对象 | 默认归属 | 可复用范围 | 默认跨范围行为 |
|---|---|---|---|
| 临时执行 Agent | 当前派发关系 | 当前局部工作 | 完成后默认解除成员关系，Agent 能力不因此弱化 |
| 会话成员 | 当前会话或协作团队 | 授权的会话、任务和下属协作 | 可重新挂接为项目成员或借调成员 |
| 项目成员 | 当前工程成员关系 | 本工程授权的会话和任务 | 经明确借调可服务其他工程，默认上下文隔离 |
| 借调成员 | 来源工程身份 + 目标工程临时关系 | 目标工程的授权任务和隔离工作会话 | 借调结束后解除目标关系，不自动合并两边私有记忆 |
| 角色模板 | 用户或产品 | 多个工程 | 只复用配置，不共享成员记忆 |
| 资源 | 工作区或外部系统 | 被多个工程、任务和会话按授权引用 | 不因被引用就共享权限或写入责任 |
| 工程资源关联 | 当前工程 | 工程内长期保留，按任务建立有效授权 | 解除关联不删除资源和历史 |
| 执行目标 | 当前 TaskAttempt | 当前执行或独立重试 | 结束后保留版本、范围和来源证据 |
| 变更集 | TaskAttempt 或人工变更 | 可检查、合并、拒绝或放弃 | 放弃不自动撤销已发生的外部副作用 |
| 合并任务 | 工程或目标资源 | 直到合并、拒绝或阻塞 | 记录冲突、检查、责任和目标版本 |

成员关系不是单向升级链。一个完整 Agent 会话可以先参与一次局部任务，再被保留为会话成员、挂接为项目成员，或经授权建立跨工程借调关系。每次关系变化必须明确来源、目标工程、任务范围、权限、可见上下文、责任与结束条件，但不需要重新创建一个能力缩水的 Agent。

跨工程借调必须显式建立目标工程关系和隔离工作会话。来源工程的私有会话、记忆和权限不自动开放给目标工程；目标工程内容也不自动回写来源工程。借调成员可以保留同一 Agent 身份，但不同工程的任务、上下文、责任和成本必须分别记录。

## 八、关键区分

### 调用子 Agent 与进入 CEO 模式

代理模式可以调用多个 Agent。只有当团队分工、依赖、进度和协调成为当前工作的主要结构时，才进入 CEO 产品体验。

### Agent 身份与会话

Agent 是具有职责和记忆的参与者；会话是它处理连续工作或某项任务的执行空间。一个项目成员可以拥有多个会话，一个普通会话也可以包含多个会话成员。

### 工作空间共享与组织共享

多个会话可以读取同一批文件，但不能因此互相调用对方的会话成员。多个工程也可以位于同一工作空间，但项目身份、记忆、权限和汇报关系默认隔离。

### 默认工作位置与资源写入

默认工作位置只是入口，不代表任务一定修改这里。每个任务必须明确目标资源和写入范围。同一资源的同一重叠写入范围，在同一版本基线和同一时间只能有一个主动变更责任主体；不同资源、不重叠范围和独立修改空间可以并行。

### 项目专属成员与角色模板

复用模板不等于复用成员。项目 A 的 PM 只向项目 A 的成员派发，项目 B 的 PM 只向项目 B 的成员派发，即使两边成员具有同样角色名称。

## 九、待决策

- 任务、子任务、任务会话、回合和运行实例的最终定义及层级
- 不同工作形态下当前责任人、责任移交和统一最终状态的规则
- 动态 Agent 会话的保留、归档、唤醒、数量和委派深度限制
- 跨会话上下文读取、下属会话读取和跨工程借调的技术实现边界
- 项目成员的停用、归档和版本变化如何表达
- 用户直接给项目成员派发任务后，PM 如何自动感知和重排计划
- 跨工程专家邀请的授权、上下文隔离和时间冲突如何处理
- 产物是否需要独立于文件的统一实体
